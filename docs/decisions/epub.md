# EPUB decisions

Deliberate decisions of the EPUB extractor (`extractors/epub.py`): what of the package is read and in which order, how a chapter is prepared for the HTML extractor, pictures, DRM, and the bounds on hostile packages. The rule is the same as in [extractors.md](extractors.md): do not revert the decisions in this table. To change one, change its pinning test first and write the reason in the same row. How a chapter's HTML becomes Markdown is decided in [html.md](html.md).

| Decision | Why | Pinned by |
| --- | --- | --- |
| The reading order is the spine of the package document (`META-INF/container.xml` → OPF → manifest → spine), not the manifest order or the file names. The chapters are joined into one `DOCUMENT` section. Package elements are matched by local name (EPUB 2 and 3, and packages without the namespace, are read alike) | The manifest is an inventory in arbitrary order; file names sort `ch10` before `ch2` | `test_epub.py::TestStructure::test_chapters_are_joined_in_spine_order_not_manifest_order`, `test_epub.py::TestStructure::test_package_at_the_archive_root_resolves_chapters_in_subfolders` |
| Each chapter is converted by the HTML extractor (`extract_html`) on its own; its pictures are registered again as pictures of the book and its warnings are merged once each (same way as a DOCX `w:altChunk`) | One Markdown dialect for HTML everywhere; a broken chapter cannot disturb the others; the character limit can stop between chapters | `test_epub.py::TestStructure::test_headings_lists_tables_and_code_come_through_the_html_extractor`, `test_epub.py::TestPictures::test_pictures_of_later_chapters_are_numbered_after_the_earlier_ones` |
| `dc:title` (the first), every `dc:creator` (joined with `, `, at most 20) and `dc:language` go to `metadata` as `title`, `author`, `language`, each cut at 500 characters. The title is not added to the text as a heading | Same keys as the other extractors. Books carry their title on a title page; adding it would repeat it | `test_epub.py::TestStructure::test_title_authors_and_language_come_from_the_package_metadata` |
| Left out without a warning: the navigation document (`properties="nav"`) and the NCX, spine items with `linear="no"`, a document listed in the spine a second time (by idref or by a second manifest item with the same href), pages without any text or picture | The navigation documents repeat every heading as a link to a file name. Non-linear items are pop-up notes, answer keys and enlarged pictures that a reading system shows only on request. A repeated entry would repeat the chapter. Known accepted gap: an EPUB 2 contents page that is an ordinary XHTML chapter (`<guide type="toc">`) is kept, as a list of the chapter titles | `test_epub.py::TestReadingOrder::test_navigation_document_and_ncx_are_not_read`, `test_epub.py::TestReadingOrder::test_non_linear_spine_items_are_left_out`, `test_epub.py::TestReadingOrder::test_document_listed_twice_in_the_spine_is_read_once`, `test_epub.py::TestReadingOrder::test_blank_page_leaves_no_gap_and_no_warning` |
| A page without text is the cover, and is left out with its picture, when the package says so: every picture on it is the cover picture (manifest `properties="cover-image"`, or EPUB 2 `<meta name="cover">`), or the `<guide>` names the page as `cover`. Any other page of pictures only is kept for its pictures | The cover is packaging, not content, and would be sent to the vision model for every book. A full-page illustration between chapters is content. Guessing the cover from file names ('cover.xhtml') was not done: it is not in the specification and a wrong guess loses a picture silently | `test_epub.py::TestReadingOrder::test_cover_page_without_text_is_left_out`, `test_epub.py::TestReadingOrder::test_page_of_pictures_that_is_not_the_cover_is_kept` |
| A page whose whole text is one heading, followed by a chapter that opens with the same heading, is dropped (the heading is written once) and its characters are taken off the count again. A title page that says anything more is kept | pandoc writes a title page holding only `<h1>title</h1>` before a document that opens with the same `<h1>`; the title came out twice. The count given to `Extraction.count` must never be larger than the real text | `test_epub.py::TestReadingOrder::test_title_page_repeating_the_first_heading_is_written_once`, `test_epub.py::TestReadingOrder::test_title_page_with_its_own_content_is_kept`, `test_epub.py::TestLimits::test_book_exactly_at_the_limit_is_not_reported_as_exceeded` |
| A chapter is parsed as XML first (entities not expanded, no network) and re-written as UTF-8 HTML for the HTML extractor, `<style>` and `<script>` left out (their text is raw in HTML, so a CDATA section holding `</style><p>…` ended the element early and the rest came out as text); a chapter that is not well-formed XML (`&nbsp;` without a DTD, unclosed tags, nesting deeper than 256) is decoded with `decode_text` (XML declaration or meta charset as the declared charset) and read with lxml's HTML parser instead | XHTML is XML: read as HTML, a CDATA section is a comment (its text vanished) and prefixed elements (`<h:h1>`) are unknown tags (headings and lists became one run of text). Reading systems show ill-formed chapters, so they are not rejected. An entity defined in a chapter is never expanded: it comes out as the literal `&name;` | `test_epub.py::TestChapterMarkup::test_cdata_sections_and_prefixed_xhtml_elements_are_read_as_xml`, `test_epub.py::TestChapterMarkup::test_chapter_that_is_not_well_formed_xml_is_read_as_html`, `test_epub.py::TestChapterMarkup::test_chapter_in_a_legacy_korean_encoding_is_decoded`, `test_epub.py::TestChapterMarkup::test_entities_defined_in_a_chapter_are_not_expanded`, `test_epub.py::TestChapterMarkup::test_self_closed_elements_do_not_swallow_the_rest_of_the_chapter`, `test_style_holding_a_closing_tag_in_cdata_shows_nothing` |
| Known accepted gap: lxml's HTML parser keeps at most 2,048 nested elements. A chapter that reaches that depth is converted as far as the parser read it, with a warning that text may be missing | No real book nests that deep; the alternative (an unbounded tree) is a way to exhaust memory. Losing the text silently was not acceptable | `test_epub.py::TestChapterMarkup::test_chapter_nested_deeper_than_the_parser_reads_is_reported`, `test_epub.py::TestChapterMarkup::test_moderately_deep_chapter_keeps_its_text` |
| Known accepted gap: a chapter that is not well-formed XML is read by the HTML parser, which takes a CDATA section for a comment, so text written inside `<![CDATA[…]]>` in such a chapter is lost | Reading systems fall back to HTML rules for these chapters too; a chapter that is both broken XML and uses CDATA for body text was not seen in a real book | - |
| Only the `<body>` of a chapter is handed on; `<head>` (and with it `<title>`) is dropped | The HTML extractor turns `<title>` into a heading when the page has none; chapter titles are generator leftovers ('ch001.xhtml') or the book title once per chapter | `test_epub.py::TestReadingOrder::test_chapter_title_element_does_not_become_a_heading` |
| `<aside>` is renamed to `<div>` before the HTML extractor sees it | The HTML extractor removes an aside outside main/article as a site side menu (`html._drop_sidebars`); in a book an aside is a footnote (`epub:type="footnote"`) or a note box. Known accepted gap: footnotes are not turned into `[^n]` references; the reference number and the note text stay where the chapter has them | `test_epub.py::TestChapterMarkup::test_footnote_aside_is_kept` |
| Links whose target is not `http:`, `https:` or `mailto:` lose their `href` before conversion (the text stays). External links are left to the HTML extractor and `options.keep_links` | `chapter2.xhtml#sec` names a file that does not exist in the Markdown | `test_epub.py::TestLinks::test_links_between_chapters_keep_their_text_and_lose_the_file_name` |
| When `options.extract_images`, an `<img>` whose `src` names a file of the package (relative to the chapter, percent-decoded, fragment ignored) gets that file as a `data:` URI before conversion. `html.py` is not changed and nothing is ever fetched: `http(s)` pictures, missing files, SVG pictures and pictures listed in `encryption.xml` keep only their alt text | `data:` URIs are the one form the HTML extractor takes pictures from, so the picture lands exactly where the chapter has it with no second code path. Known accepted gap: a picture inside an inline `<svg><image …/></svg>` wrapper is not extracted (the HTML extractor drops inline SVG), nor are `srcset` / `<picture>` alternatives | `test_epub.py::TestPictures::test_picture_of_the_package_is_extracted_where_it_stands`, `test_epub.py::TestPictures::test_pictures_are_not_read_when_image_extraction_is_off`, `test_epub.py::TestPictures::test_remote_missing_and_svg_pictures_keep_only_their_alt_text`, `test_epub.py::TestEncryption::test_encrypted_picture_is_not_extracted_but_the_text_is_read` |
| One picture is read up to 20 MB and all pictures of a book up to 64 MB in total, counting every reference; pictures beyond that keep their alt text and one warning gives their number | Every reference is held as its own picture (and as base64 inside the chapter while it is converted), so one large picture referenced on every page multiplied the memory | `test_epub.py::TestPictures::test_pictures_over_the_total_cap_keep_only_their_alt_text`, `test_epub.py::TestPictures::test_picture_larger_than_the_per_picture_cap_is_not_read` |
| A picture is decompressed only while it can still be used: one found missing, unreadable or over the per-picture cap is not read again, and one whose size is known is not read once it no longer fits in the book's total | Every `<img>` inflated its picture again up to the cap, before the total was checked: 20,000 references to one oversized picture (a 20 KB book) ran for more than a minute | `test_epub.py::TestPictures::test_unusable_picture_is_read_once_however_often_it_is_shown` |
| `META-INF/encryption.xml` makes the book an `EncryptedDocumentError` only when it lists a chapter that would be read (or the package document), whatever the algorithm. A ZIP-level password on a part that is read is the same error. An `encryption.xml` that cannot be parsed is ignored | Font obfuscation puts an `encryption.xml` into most commercial but DRM-free books, and fonts are never read. Ciphertext read as a chapter would come out as garbage. Nothing can be told from a broken `encryption.xml`, and rejecting an open book for it loses more than it protects | `test_epub.py::TestEncryption` |
| A spine entry that names no manifest item, a chapter that is not in the archive, cannot be decompressed, is larger than 32 MB or cannot be parsed is skipped, and one warning gives their number. `CorruptedDocumentError` only when no package document is found or no chapter at all could be read. Without `container.xml` (or when it is broken or points nowhere) the first `.opf` file by name is used; without a spine the XHTML documents are read in manifest order, with a warning. Spine pages that are not XHTML (SVG or picture pages) are left out with a warning | One missing chapter must not reject the book (same rule as the other extractors). Sizes stored in the ZIP are not trusted: a part is decompressed only up to its cap plus one byte | `test_epub.py::TestBrokenPackages`, `test_epub.py::TestLimits::test_chapter_larger_than_the_part_cap_is_skipped_with_a_warning` |
| A reference that is not a path inside the package (another scheme or host, an absolute path, one that climbs above the archive root with `..`) names nothing, even when the archive holds a member with exactly that name | Only archive members are ever opened, so nothing outside the file can be reached either way; refusing the names keeps crafted member names such as `../outside.xhtml` out of the result | `test_epub.py::TestBrokenPackages::test_references_that_leave_the_package_read_nothing` |
| At most 5,000 spine entries are looked at (the rest are reported in a warning); reading stops after the chapter at which `Extraction.count` reports the character limit | The work per book must be bounded by the limits, not by what the package claims; chapters after the limit were parsed only to be thrown away | `test_epub.py::TestLimits::test_spine_longer_than_the_cap_is_cut_with_a_warning`, `test_epub.py::TestLimits::test_chapters_after_the_character_limit_are_not_read`, `test_epub.py::TestLimits::test_spine_repeating_one_chapter_a_hundred_thousand_times_reads_it_once` |
| Known accepted gap: markup without text is bounded only by the sizes (`max_uncompressed_bytes` for the book, 32 MB per chapter), not by `max_chars`. Measured: 15 chapters of 31 MB of empty elements (a 0.9 MB book) took 41 s and 1.8 GB | The policy of every ZIP format: the decompressed size is the bound, and a service sets it (and runs `IsolatedConverter` for a memory limit) according to what it accepts | - |
