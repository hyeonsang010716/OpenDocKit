# CSV decisions

Deliberate decisions of the CSV extractor (`csv_text.extract_csv`) about delimiters, quotes and line verdicts. Split off from [spreadsheet.md](spreadsheet.md);
the rule is the same: do not revert the decisions in this table. To change one, change its pinning test first and write the reason in the same row. Value formatting is,
together with Excel, in [spreadsheet.md](spreadsheet.md); splitting tables within a sheet is in [spreadsheet-tables.md](spreadsheet-tables.md).

## CSV

| Decision | Why | Pinned by |
| --- | --- | --- |
| A row on which the csv module fails is read again with a quote-aware split (`_quoted_record`; only dialects with the doubled-quote rule and no escape character); when the quote closes, only that row is used and the csv module resumes from the next line (no warning). Only when the quote never closes before the end of the file is the rest, from that line on, split by delimiter alone (warning). `csv.field_size_limit` is not raised. The csv module reads in strict mode, so a quote still open at the end of the file fails too (text after a closing quote, `"a"b`, fails as well and `_quoted_record` joins it as the lenient reader did) | An unclosed quote swallowed everything after it into one cell, and once that passed the limit (131,072 characters) the whole file was rejected; below the limit the lenient reader swallowed it without any error, so the rows after the quote disappeared into one cell without a warning. The limit is a process-global setting. The delimiter-only split used instead also cut healthy cells over the limit (long body text) at every comma, so the column limit dropped the rest and the author cell (348 KB → 2,410 characters, false warning) | `test_office.py::TestCsvWithBrokenQuotes`, `test_audit_spreadsheet_fixes.py::TestUnclosedQuoteInASmallCsv` |
| CSV uses all of the Sniffer's delimiter, quotechar and skipinitialspace (the single-quote and comma verdicts are changed only under the conditions of the rows below) | `, "서울시, 강남구"` was split into two cells | `test_spreadsheet.py::TestCsvDialect` |
| A single quote in CSV is accepted as the quote character only when every cell containing it is wrapped whole (`_wraps_whole_fields`) | The Sniffer picked `'` because of a single `'목표'`, and the cell `'24년 상반기` swallowed the delimiter. `'홍길동','1,000'` is still read | `test_spreadsheet.py::TestCsvDialect::test_apostrophe_inside_a_field_is_not_a_quote_character`, `test_single_quote_as_quote_character` |
| Even when the Sniffer picked the comma (or failed), if the number of cells split by tab, semicolon or pipe is the same on every line of the sample (2 or more cells; in the order tab → semicolon → pipe), that delimiter is used (`_steadier_delimiter`). For a single-line file, tab only. When double quotes wrap cells whole under the comma but not under the candidate, the comma stays. A file whose cell count differs per line is changed only for TSV that omits trailing empty cells (row below) and the following case, otherwise the Sniffer's choice stands: when there are two or more lines with the maximum candidate cell count (3 or more cells), they are the majority, and from the first of them (the header) on the comma cell count is uneven, that candidate is used (`_delimiter_of_most_lines`; leading title/meta lines and short lines are ignored). When the comma cell count is even from the header on, the `;`/`\|` are enumerations inside values, so comma. Known accepted gap: the `.tsv` extension is not passed to the extractor and so is not used, and an unquoted comma CSV whose every line contains the same number of semicolons or pipes is split by those | With the same number of commas per line the Sniffer picked the comma, so `서울\t1,234\t5,678` became `서울 1 \| 234 5 \| 678`, and decimal commas (`1,5`) and word enumerations were split into two cells. Title/meta lines of bank and ERP exports (`Umsatzanzeige;…`, `고객 목록`) or a single line omitting trailing empty cells made the cell count uneven, and `-1.234,56` was split into `-1.234 \| 56` (the earlier decision 'when the cell count differs per line, keep the Sniffer's choice' was changed with the owner's approval) | `test_spreadsheet.py::TestCsvDialect::test_delimiter_with_a_steady_column_count_wins_over_commas_inside_values`, `test_tab_delimiter_is_found_in_a_file_longer_than_the_sample`, `test_comma_file_with_other_delimiters_inside_values_stays_comma_delimited`, `TestCsvDelimiterOfMostLines` |
| TSV whose tab count differs per line because trailing empty cells are omitted: when the Sniffer picked the comma, the comma cell count is uneven, the first line has a tab and every line containing a comma has a tab (2 or more lines with tabs; only when double quotes wrap cells whole by tab), it is tab (`_tab_on_every_comma_line`) | The amount `1,100,000` in Excel/ERP TSV exports was split at the thousands separators and the columns shifted. A comma CSV has lines with commas but no tab, or no tab in the header | `test_spreadsheet.py::TestCsvDialect::test_tab_file_whose_rows_omit_trailing_empty_cells_is_tab_delimited`, `test_comma_file_with_some_tabs_stays_comma_delimited` |
| A CSV line with more delimiters than the column limit is cut before parsing to the column limit + one 'overflow marker' cell. Lines containing the quote character and lines inside an open quoted cell (decided by the parity of the quote count) are not cut (Known accepted gap: such lines stay large). When the first line is only `sep=X`, that delimiter is used and the line removed (the Sniffer is restricted to that delimiter) | A single line with 22.5 million commas (45 MB) built every cell object: 5.2 s, 1.55 GB (→ 0.4 s). Excel's `sep=;` marker line became the header and was not used for the delimiter verdict | `test_spreadsheet.py::TestCsvLimitsAndHints` |
| When a whole CSV cell is `="…"` (the Excel idiom for keeping leading zeros), it is unwrapped to the text inside (`""` → `"`). Other formulas stay as they are | `="00123"` came out as is | `test_spreadsheet.py::TestCsvExcelTextFormula` |
| Only when every backslash in the sample (first 8,192 characters) is in front of a character that MySQL `INTO OUTFILE` escapes (`"`, `\`, `N`, `0`, `n`, `t`, `r`, `b`, `Z`, the delimiter, a line break), there is a place where `\"` is followed by a character that is not the end of a cell, and the sample read with `\"`→`""` and `\\`→`\` has the same cell count on every line with double quotes wrapping cells whole, is the file read that way (`_escapes_quotes_with_backslashes`). `\N` (NULL) and the like stay literal. Known accepted gap: when `\"` occurs only after the sample it is not recognized, and a file mixing both rules (`"Is it \"ok\"?"` and a path ending `"c:\"`) is read with the doubled-quote rule as before | Read only with the doubled-quote rule, `"27\" 모니터"` became `27\ 모니터"`. Reading an ordinary CSV with other backslashes (`C:\temp`, `\d+`) as escapes loses characters | `test_core_spreadsheet.py::TestCsvBackslashEscapes` |
| Even with `.csv`/`.tsv`, when the very start after BOM and whitespace is an HTML document tag (`<!doctype html`, `<html`, `<table`, `<head`, `<body`, `<style`, `<meta`) and the first 64 KB contain a table tag (`<table`, `<tr`, `<td`) together with its closing tag, the file is read as HTML with an extension warning (`detect._is_html_table_export`). A real CSV whose first cell starts with a tag (`<b>굵게</b>,…`, `<table>,<tr>` without closing table tags) is CSV. `.txt` stays text (among text formats the extension decides) | When an 'Excel download' serves an HTML table as `.csv`, the tags became cell text and `1,000` was split into two cells. Of 2,035 real CSV/TSV files from systems, 0 changed to HTML (owner's approval, conservative) | `test_core_text_and_mail.py::TestHtmlTableServedAsCsv` |
