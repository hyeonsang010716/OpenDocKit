# Spreadsheet table decisions

Deliberate decisions about splitting tables within a sheet (Excel, CSV) at empty rows and columns, title rows, summary cells, filling merges and the start column of the column limit (`spreadsheet._sheet_text`, `_fill_across`). Split off from [spreadsheet.md](spreadsheet.md);
the rule is the same: do not revert the decisions in this table. To change one, change its pinning test first and write the reason in the same row.

| Decision | Why | Pinned by |
| --- | --- | --- |
| The top row of a table is a table title, put in a paragraph above the table, when only one cell is filled, or when in a table of 4 or more columns only two cells are filled and the second is a unit or as-of note (`(단위: 천원)`, `[기준 …`, `기준일:`) ('title (단위: 천원)'; `markdown._title_of` — common to every format). A two-cell row only when it is a unit or as-of note | The row 'title \| \| \| \| (단위: 천원)' became the header and the real header a data row (XLSX, .xls exported as HTML). Parent headers ('상반기 \| \| 하반기') and headers of narrow tables stay as they are | `test_markdown.py::TestRenderTable::test_lifts_title_row_with_a_unit_note_above_table`, `test_two_cell_top_row_that_is_not_a_title_stays_the_header`, `TestMergedTableAsHtml::test_title_row_with_a_unit_note_is_a_paragraph_above_an_html_table`, `test_spreadsheet.py::TestTitleRowWithUnitNote` |
| A sheet (CSV included) is split into chunks at empty rows (`_sheet_text`), and a chunk is rendered as a new table when its first table row (after a leading single-cell title row) equals the header of the previous table, or looks like a header (two or more cells that are all non-numeric text — a year is text; a number with a unit attached such as `1,200원` or `12명` is a number (`_UNIT_SUFFIX`; 월, 년, 차 excluded) — and there is a column where a number comes within 5 rows below those text cells; `_looks_like_header`) and is preceded by a title (inside the chunk, or the single-cell chunk right before it) or has a different number of columns. A chunk made only of rows with just the leftmost cell filled, not a number or formula (titles, '※ 출처' source notes), is a paragraph when a new table follows or the sheet ends, and rows of the table when the same table continues. When there is nowhere to split, the whole sheet is one table as before (`render_table`). Full-load XLSX yields skipped row numbers, and Excel 2003 XML skipped `ss:Index` and empty `Row`, as a single empty row. Known accepted gap: a table with text only (no numeric column) is split only when the headers are equal, and when the first data row after a group-name row ('[개발팀]') has text ('결시', absent) in a numeric column, it is split there. Streaming XLSX has no merge information, so a row with only merged cells is an empty row too | In a report form, the '2. 인원' (headcount) table below the '1. 매출' (sales) table became data rows of the first table and the header '부서 \| 정원 \| 현원' went into the columns '사업부 \| 1월 \| …' (likewise [거래 요약] / [거래 내역] in a bank CSV). Values with a unit format (`#,##0"원"`) looked like text and the second table was merged again. A single empty row alone does not split because a single table with an empty row before the total or between groups is common | `test_spreadsheet.py::TestSeveralTablesInOneSheet`, `test_core_spreadsheet.py::TestTablesWithUnitFormats`, `TestXlsxRowsFarApart`, `TestXlsResourceBounds::test_far_cell_does_not_make_every_row_full_width` |
| For a horizontal merge in Excel (full-load XLSX, XLS, Excel 2003 XML) the spanned cells are remembered only when there is text to the left in the same row (`_repeat_merge`, `_Across`), and after the sheet is split into tables, the value is repeated into those cells only in rows where every spanned column has text in a row above (header etc.) within that table (`_fill_across`). Vertical-merge repetition (`_repeat_down`) and the limit (`_MAX_MERGED_CELLS`) are as before; a two-dimensional merge follows the vertical rule for the left column and the horizontal rule for the rest. In the first row of a table (header or title row), for a merge that starts at the leftmost column or has nothing to its left (table title, '[개발팀]'), and for a merge that reaches into unnamed empty columns (quotation '합계금액 \| 일금 … 원정'), the value is in the first cell only. Known accepted gap: parent headers in the header row ('1월' spanning 목표/실적) are not repeated; streaming XLSX has no merge information | A merge of '육아휴직' (parental leave) across March–April in a data row stayed in the first cell only and the other month read as blank (the README's 'merge information is spread over the cells and the result is always Markdown'). Filling before splitting tables made the query-condition row ('조회기간 … \| (단위: 원)') the header of the main table and merged the head cells of a quotation into the main table (r32 reproductions erp, quote) | `test_core_spreadsheet.py::TestHorizontalMergesInDataRows` |
| Within one table split off at empty rows, when every row including the header is divided by empty columns (a column spanned by a horizontal merge is not empty) into column groups that are each a table in their own right, each group is rendered separately (`_side_by_side`). A table in its own right = two or more columns, a header row (the first row with two or more filled cells) of text that is not numbers or formulas, and a non-numeric name in the data cells of the first column (`_is_side_table`). Horizontal-merge filling is done on the whole table before splitting (columns spanned by a merge are not split, so the result is the same). Known accepted gap: a single table with name columns on both sides and an empty spacer column ('성명 \| 부서 \| \| 비상연락 \| 관계') is split too — the row order is unchanged. A group with numbers only (the right side of '1월 \| 2월 \| \| 7월 \| 8월') and a single-column group stay one table | Two side-by-side tables separated by one empty column were merged into one, and '김대리' read as the person in charge of the Seoul branch (real CSV: a course list \| \| a '추가 업데이트 필요 강의' table were paired row by row). A single-cell row at the top of each group ('[입고]') is that table's title (`render_table`) | `test_core_sheet_layouts.py::TestSideBySideTables` |
| When, at the right end of the header row, columns whose data rows below are all empty hold numbers or formulas and the remaining header looks like a header (`_looks_like_header`), those cells are detached into a paragraph above the table ('총원 26', total headcount 26) (`_header_summary`). Empty columns without a number ('비고'), year column names ('2023') and the head cells of a quotation ('수신 \| … \| 견적일 \| 2024-03-05') stay as they are | A summary value put next to the header, as in the header '본부 \| 팀 \| 인원 \| 총원 \| 26', became a column name | `test_core_sheet_layouts.py::TestSummaryCellsRightOfTheHeader` |
| The column limit (`max_sheet_cols`) counts from the leftmost column that has a value: full-load XLSX (`_first_used_column`; sheets with formula cells without values excluded) and XLS (`_xls_first_used_column`) read rows without the empty columns to its left and shift merge positions by the same amount (a merge starting in a removed column has an empty first cell and is ignored). Known accepted gap: streaming XLSX (merges and the sheet range are not trusted), Excel 2003 XML and CSV count from column A as before | Counting from column A made the last 4 columns of a 10-column table starting at column CQ disappear with a warning. The limit is there to bound the width of the table | `test_core_sheet_layouts.py::TestColumnLimitFromTheFirstUsedColumn` |
