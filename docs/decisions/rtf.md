# RTF decisions

Deliberate decisions of the RTF extractor (`extractors/rtf.py`). The rule is the same as in [extractors.md](extractors.md): do not revert the decisions in this table. To change one, change its pinning test first and write the reason in the same row.

| Decision | Why | Pinned by |
| --- | --- | --- |
| RTF is read by the library's own reader: one pass of one token regex (control word with a number of at most 10 digits, `\'hh`, control symbol, brace, text) feeding a state machine with a group stack kept in a list. No dependency, no recursion, no look-back | The format is a public upload format (Korean public-sector forms, mail attachments); the available pure-Python readers return plain text only (no tables, headings or code pages per font). A list stack and bounded token shapes keep the time linear whatever the file claims: 2 MB of unclosed braces, of control words, of escapes or of one hex blob each read in about a second or less | `test_rtf.py::TestHostileInput::test_time_is_linear_in_the_size_of_the_file`, `test_number_with_thousands_of_digits_is_not_parsed_as_one_number` |
| Character formatting and the destination follow the group stack; paragraph properties (style, outline level, list, table depth) and the row definition do not — they belong to the text flow, last until `\pard` / `\trowd`, and are read when the paragraph or row ends. Known accepted gap: a writer that relies on a closing brace to restore paragraph properties (none seen) keeps the inner ones | Word closes a run group after `\par`, pandoc wraps each paragraph in a group, LibreOffice writes the list reference after the `\listtext` group: scoped to groups, the heading level or list level was lost at the brace | `test_rtf.py::TestParagraphsAndHeadings::test_par_inside_a_group_uses_the_properties_set_outside_it`, `test_paragraph_properties_last_until_pard` |
| The bytes of a run (`\'hh` and plain text alike) are collected and decoded together, with the code page of the current font (`\fcharsetN`, `\cpgN`), else of the document (`\ansicpgN`, `\mac`, `\pc`, `\pca`; CP1252 when nothing is said). Invalid bytes become U+FFFD; an unknown code page or charset falls back to the document's, and so does a code page that does not read letters, digits, backslash and braces as ASCII (only the EBCDIC pages 273, 424, 500, 875, 1026, 1140 among 1–99999; CP864, which draws '%' as '٪', is still used) | A CP949 syllable is two `\'hh` (or one `\'hh` and a plain letter); decoded byte by byte Korean text was '°¡' noise. A wrong declaration must not reject the document. RTF is ASCII text: with an EBCDIC `\ansicpg875` a run holding one 8-bit byte had its letters decoded as EBCDIC too ('hello' → 'ΪΧ%%?') | `test_rtf.py::TestCharacters::test_cp949_double_byte_escapes_become_hangul`, `test_font_charset_selects_the_code_page_of_a_run`, `test_trail_byte_written_as_a_plain_letter_completes_the_character`, `test_code_page_that_is_not_ascii_compatible_is_ignored`, `TestHostileInput::test_wrong_encoding_does_not_fail` |
| A font with `\fcharset0` (ANSI) in a document whose code page is double-byte (932, 936, 949, 950, 1361) is decoded with the document's code page when the bytes are valid there, otherwise as CP1252. Known accepted gap: two accented Western letters in a row in such a font and document ('éé') are valid CP949 and read as one CJK character | Generators that declare every font as ANSI still store Hangul in the document's code page. Strict Word behaviour (charset 0 is always CP1252) turned such documents into noise, while 'café ' is not valid CP949 and still reads correctly | `test_rtf.py::TestCharacters::test_ansi_charset_font_in_a_korean_document_reads_hangul` |
| `\uN` is a signed 16-bit value (negative above U+7FFF); a surrogate pair is joined, a half without its pair is dropped. After it, `\ucN` fallback characters are dropped — counted over `\'hh` and text bytes only, and the dropping stops at the next control word or brace. When the dropped bytes are only the start of the escaped character in the run's code page, the bytes right after them (`\'hh` or plain 8-bit text, in the same run of text or the next token) are dropped too while they continue that character and until it is complete (`rtf._Reader._drop`, `_drop_trail`); a control word or brace in between ends this, like the dropping itself. Nothing else is dropped with a fallback: a byte that only makes some other character of the code page with the dropped bytes is text; so is the byte after one byte that is the escaped character in CP1252 when the font is `\fcharset0` or not named; and so is the byte that completes the escaped character when the text right after it (16 bytes are looked at, `_text_ahead`) cannot be read without it and can with it. The dropped bytes are looked at only when a byte follows them. `\uc` outside 0–16 is the default 1. Known accepted gap: a fallback that is only the first byte of the escaped character (half a character, which the specification does not allow), followed by text that starts with the second byte of that same character and reads either way, is the same bytes as a fallback counted in characters and is read as one — that byte is dropped. The other way round, in a `\fcharset0` or unnamed font of a Big5 document a '¢' whose fallback is counted in characters (0xA2 0x46) keeps an 'F': the specification's reading (one CP1252 byte, then the letter F) wins | A lone surrogate cannot be encoded as UTF-8 and failed the whole result. Counting control words as fallback characters (the letter of the specification) ate `\par` after writers that put no fallback; `섀0000` would have swallowed the rest of the run. Writers that count `\ucN` in characters write `\uc1\u44032\'b0\'a1` for '가', and the stray second byte came out as '가�'; the byte is dropped only when it completes the escaped character itself, so a fallback counted in bytes and a one-byte fallback followed by real text read as before. Dropping it whenever the pair was any character of the code page took the letter after the one-byte fallback Word writes in a Western font of a Chinese, Japanese or Korean document (`\uc1`, the escape for '’', `\'92s`: 0x92 0x73 is a GBK character) — "It’s a cafés" became "It’ a café", 942 of 4,457 such runs in a comparison of 30,000 generated documents. A fallback written to the specification (whole characters, `\ucN` bytes) loses nothing after it. Measured on 150,000 generated documents whose text is known (code pages 932, 936, 949, 950, 1251, 1252, 65001; `\uc0`–`\uc2`; fallbacks written as `?`, `\'hh`, raw bytes or left out; a `\fcharset0` font, the font of the code page, no font table): every document that was read correctly without this rule still is, except 11 of the 10,700 with the half-character fallback of the gap; 24,000 with a fallback counted in characters are read correctly because of it. Decoding the dropped bytes after every `\uN` made documents of double-byte fallbacks 75% slower; after a correct fallback the next token is nearly always a control word, so they are looked at only when a byte follows | `test_rtf.py::TestCharacters::test_unicode_escapes_cover_negative_values_and_surrogate_pairs`, `test_fallback_counted_in_characters_drops_the_whole_double_byte_character`, `test_fallback_written_as_raw_8bit_text_is_dropped_whole`, `test_one_byte_fallback_never_takes_the_letter_after_it`, `test_byte_that_the_text_after_it_needs_is_not_dropped`, `test_uc_sets_how_many_fallback_characters_are_dropped`, `test_fallback_skipping_stops_at_a_control_word_or_brace`, `TestHostileInput::test_absurd_uc_value_does_not_swallow_the_text` |
| A group that starts with `\*` and a destination that is not known is skipped whole, as are the known non-text destinations (font, color, file and revision tables, index entries, bookmarks, annotations, object data, theme data, `\nonshppict`, `\shprslt`, `\nonesttables`, `\listtext`, `\pntext`). An unknown control word without `\*` is formatting and keeps its text. `\*` that is not the first thing in its group and stands in front of a style reference (`\cs`, `\s`, `\ds`, `\ts`) is formatting: StarWriter wrote `{\b0\*\cs7 text}`, and skipping that group left the whole document empty. In front of any other unknown word it still skips the rest of the group, wherever it stands. `\v` hidden text and `\deleted` tracked deletions are left out | The format's own rule for forward compatibility; without it font names, color tables and hex data became body text. Deleted text read as valid text (same direction as DOCX `w:del`) | `test_rtf.py::TestSkippedDestinations::test_tables_of_fonts_colors_and_ignorable_groups_are_not_text`, `test_unknown_control_words_do_not_hide_their_text`, `test_star_in_the_middle_of_a_group_does_not_hide_its_text`, `TestCharacters::test_hidden_and_deleted_text_is_left_out` |
| `\info`: only `\title` and `\author` are read, into `metadata`; nothing of it is body text | Same metadata as the other document formats | `test_rtf.py::TestParagraphsAndHeadings::test_title_and_author_become_metadata_and_other_properties_do_not` |
| Headings: `\outlinelevelN` on the paragraph (0–8; 9 and above mean body text even on a heading style), else the paragraph style or a style it is based on (10 hops) named 'heading N' / '제목 N' / 'Title' / '제목' or carrying its own outline level. Not inside a table cell or footnote, not over 120 characters, no emphasis, line breaks joined with a space. Known accepted gap: the automatic number of a numbered heading is not reproduced (it is only in the skipped `\listtext`) | The DOCX rules (`docx._heading_level`, `_HEADING_MAX_CHARS`), so the same document gives the same headings in both formats | `test_rtf.py::TestParagraphsAndHeadings::test_headings_come_from_style_names_in_english_and_korean`, `test_outline_level_on_the_paragraph_makes_a_heading`, `test_long_paragraph_with_a_heading_style_is_body_text`, `test_heading_text_has_no_emphasis_and_joins_its_lines` |
| Lists: `\lsN` → list override → list → `\levelnfcN` of the level `\ilvlN` names: 23 is a bullet, 255 no mark (a plain paragraph), anything else a number; a list missing from the table is a bullet list. Numbers are counted by the reader per `\ls` (sub-levels restart, `\levelstartat` honored) and always written `N.`; the writer's `\listtext` copy is skipped. A 'List Bullet 2' style name gives the indentation when `\ilvl` is 0. The older `\pn` paragraphs: `\pnlvlblt` bullets, the rest numbers that start over after a paragraph outside the list. Inside a cell the level is `cell_level_mark`. Known accepted gap: letter and roman numbering comes out as `1.`, `2.` | `\listtext` holds a glyph of a symbol font for bullets (private-use, removed by cleaning) and is absent in some writers, so it cannot be the source. `N.` is the only numbered form Markdown and `join_blocks` read as a list item | `test_rtf.py::TestLists::test_bullet_and_numbered_lists_from_the_list_table`, `test_list_without_a_definition_is_a_bullet_list`, `test_list_level_without_a_number_is_a_plain_paragraph`, `test_list_bullet_2_style_is_one_level_down`, `test_older_pn_numbering` |
| A paragraph outside any list that starts with a typed bullet (`•`, `–`, `·`, …) followed by a tab is a `- ` item; its level is the place of its `\li` indent among the items before it. A typed `1.` + tab already reads as a numbered item | pandoc writes every list this way (no list table); the items came out as separate '• text' paragraphs | `test_rtf.py::TestLists::test_typed_bullet_followed_by_a_tab_is_a_list_item` |
| Links and emphasis follow the shared rules of [inline-formatting.md](inline-formatting.md) and are not decided here: the reader only says where a span starts and ends (`rtf._inline_tokens`) and `_inline.resolve_inline` / `_inline.link_target` write the Markdown — run merging, whitespace outside the marks, whole-block and part-of-word emphasis, no emphasis in headings, address filtering and escaping, link text that is its own address. Footnote text goes through the same rules | The same content must give the same Markdown as DOCX. The reader first had its own rules and wrote a paragraph or header cell that is bold as a whole as `**…**`, which DOCX leaves unmarked | `test_rtf.py::TestEmphasis`, `TestLinks` |
| RTF-specific sources of the spans. Emphasis: `\b` / `\i` in force on the run (group-scoped; off with `0` or `\plain`) — character and paragraph styles are not followed, as in DOCX. Links: the result (`\fldrslt`) of a field whose instruction is `HYPERLINK "address"` (quoted or bare), with `\l "bookmark"` appended as the fragment; a bookmark-only link (`HYPERLINK \l "name"`) and other fields keep only the result text, and the instruction is never text. A picture or footnote reference inside a link result stays in the link's span. Underline, strike, color and size are not kept | The instruction is code, not text. The same field shapes as `_inline.field_link`, so a document saved in both formats links the same words | `test_rtf.py::TestSkippedDestinations::test_hyperlink_field_becomes_a_link_around_its_result`, `test_mailto_link_and_whitespace_stay_outside_the_brackets`, `TestLinks::test_bookmark_is_appended_as_the_fragment`, `test_link_around_a_picture_keeps_the_picture_and_writes_no_link`, `TestEmphasis::test_plain_resets_emphasis_and_whitespace_only_runs_get_no_markers` |
| The spans are handed to the shared resolver as `InlineMark` items between the pieces of text (the HTML way), not as control characters inside the text (the DOCX / PPTX way: `mark_emphasis`, `LINK_OPEN` / `link_close`, `merge_emphasis_marks`, `plain_inline`) | Those helpers mark spans with U+000E–U+0014, which XML text cannot hold but RTF text can (`\'12`, `\u19`): a document could have written a link or bold span it does not have. The resolver merges neighbouring pieces itself, and the text without marks is simply the joined runs, so nothing of those helpers is reimplemented | `test_rtf.py::TestLinks::test_control_characters_in_the_text_cannot_forge_a_link` |
| `\footnote` (also the `\*\footnote` pandoc writes): `[^n]` where the group is, numbered in order of reference, definitions at the end on one line each (a table inside is 'cell / cell; cell / cell'). A footnote without text leaves no reference; a footnote inside a footnote is left out; nothing is kept when `include_footnotes` is off. Footnote text is not counted toward the character limit while reading (as in DOCX) | Same shape as DOCX/HWP. The `\chftn` mark is not text | `test_rtf.py::TestSkippedDestinations::test_footnotes_become_references_with_definitions_at_the_end`, `test_empty_footnote_leaves_no_reference`, `TestTables::test_table_inside_a_footnote_is_one_line` |
| `\header` / `\footer` and their left/right/first-page variants are read only with `include_headers_footers`: each distinct text once, headers before the body and footers after it | The first-page and odd/even variants usually repeat one text. Same placement as DOCX | `test_rtf.py::TestSkippedDestinations::test_headers_and_footers_follow_the_option` |
| The text of a shape (`\shptxt` inside `\shpinst`, `\dptxbxtext` inside `\do`) is read as its own paragraphs, placed before the paragraph that anchors the shape; shape properties (`\sp`) and the `\shprslt` copy are skipped | Text boxes hold real content in Korean forms; the property names and the compatibility copy are not content | `test_rtf.py::TestSkippedDestinations::test_shape_text_is_read_once_and_its_properties_are_not` |
| Table cells are placed when the table ends, by the right edge (`\cellx`) of each cell among the edges of all rows (edges within 30 twips are one edge): a cell covering several edges spans those columns. A row uses the definition in force at its `\row` (Word writes it after the cells, LibreOffice before); a definition is kept until the next `\trowd`. When a row has more cells than edges or edges that do not increase, every row of that table is placed cell by cell. Cells after the last `\row` are a row | RTF has no column span attribute: Word stores a span as one wider cell. Placing by cell order shifted every column after a span | `test_rtf.py::TestTables::test_wider_cell_spans_the_columns_its_edges_cover`, `test_row_definition_after_the_cells_is_used`, `test_row_without_cell_edges_is_placed_in_order`, `test_cells_after_the_last_row_end_are_kept` |
| Merged cells go through `TableGrid` by the DOCX rule: `\clvmrg` cells become the row span of the cell above when they are as wide as it (Markdown repeats the value on each row), `\clmrg` cells extend the column span of the cell before them. A merged-away cell that has text is an ordinary cell | One rule for every format. Dropping the text of a 'merged' cell lost content in files that set the flag wrongly | `test_rtf.py::TestTables::test_vertically_merged_cells_repeat_their_value_on_every_row`, `test_horizontally_merged_cells_become_one_spanning_cell`, `test_merged_away_cell_with_text_keeps_its_text` |
| A nested table (`\itapN`, `\nestcell`, `\nestrow`, row definition in `\*\nesttableprops`) is handed to the outer `TableGrid` (`embed`) at the place it has in the cell; the nested definition is kept apart from the outer one; depth is capped at 16 | Same as DOCX. LibreOffice writes the outer definition only before the cells, so one shared definition gave the outer row the inner edges | `test_rtf.py::TestTables::test_nested_table_keeps_its_rows_and_columns`, `TestHostileInput::test_absurd_table_nesting_depth_is_bounded` |
| A top-level table of the body checks the character limit cell by cell (`_notation.TableBudget`), and paragraphs are counted as they end; reading stops there and that is not reported as truncation | A table of many rows was otherwise built whole before the limit was noticed | `test_rtf.py::TestLimits` |
| Pictures: the data of a `\pict` group (hex, or raw after `\binN`) is registered with `add_image` where the group is, whatever the type (`\pngblip`, `\jpegblip`, `\emfblip`, `\wmetafile`, …) — the converter decides what is readable. `\nonshppict` copies and `\*\blipuid` are skipped; non-hex characters and an odd last digit are ignored. At most 10,000 pictures per document (one warning). Alternative text is not read | Word and LibreOffice write each picture twice (PNG and a WMF rendering). A file of only tiny pictures would register millions | `test_rtf.py::TestPictures` |
| Bounds: groups deeper than 500 are not read (warning); `\binN` past the end of the file takes what is there; a row definition holds at most 4,096 cells and is stored once per definition, not per row; list levels 64; field instructions 4,096 characters (one long piece is cut too) and the link of a field is worked out once, not at every `\fldrslt`; pieces of text that follow each other with the same formatting are collected as one run (white space, a picture placeholder and a footnote mark stay runs of their own, so the marks come out as they did with one run per piece); a paragraph has at most 50,000 runs (`_MAX_PARAGRAPH_RUNS`) — what follows is read as one last run without bold, italic or link, so no text is lost; a table keeps at most 500,000 cells (`_MAX_TABLE_CELLS`) — the cells after that are left out, with or without a `\row`, and one warning says so, while a row inside the limit keeps every cell; numbers of more than 10 digits are not numbers | Each was a way to make the reader slow or large with a few bytes. Measured before the bounds: a 3 MB instruction with 1,000 results 11 s; 10 million `\_` in bold (20 MB) 22 s and 4.6 GB; 4,000 rows of 1,000 empty cells (20 MB) 13 s and 3.4 GB; one paragraph of 2.8 million `{\b a}b` (20 MB) 16 s and 2.3 GB. Known accepted gaps: a `HYPERLINK` address longer than the instruction cap loses its link (the text stays); compared with one run per piece, 16 of 120,000 random documents differ in where a mark is written, none in text | `test_rtf.py::TestHostileInput` (`test_long_field_instruction_with_many_results_is_cheap`, `test_pieces_with_the_same_formatting_are_one_run`, `test_cells_past_the_cell_limit_of_a_table_are_left_out_with_a_warning`, `test_paragraph_of_endless_runs_keeps_its_text_in_a_bounded_number_of_runs`, …), `TestEmphasis::test_emphasis_is_marked_line_by_line_inside_a_run` |
| Data without `{\rtf` at its start (after an optional byte order mark and blank space) is `CorruptedDocumentError`. A file that ends inside its groups, inside a control word or inside `\bin` data keeps what was read, with one warning. Whatever follows the closing brace of the document is ignored without a warning | A cut-off upload still has most of its text. Mail gateways append bytes after the document | `test_rtf.py::TestHostileInput::test_data_that_is_not_rtf_is_a_corrupted_document`, `test_truncated_document_keeps_what_was_read_with_a_warning`, `test_text_after_the_document_group_is_ignored`, `test_binary_length_past_the_end_of_the_file_is_cut_to_the_file` |
| Known accepted gaps (not read): equations (`\*\moMath`; LibreOffice drops them when saving RTF), comments (`\*\annotation`), text of symbol fonts (Symbol, Wingdings — it lands in the private-use area and is removed), HTML wrapped in RTF by Outlook (`\fromhtml`: the `\*\htmltag` groups are skipped, so only the plain-text rendering is read), embedded OLE objects (only their preview picture), underline/strike/superscript | No sample documents to confirm the shapes; each is skipped cleanly rather than guessed | — |
