# Image decisions

Deliberate decisions about images, picture descriptions (the describer) and image placeholders. Split off from the common decision table in [core.md](core.md).
The per-format rules for extracting pictures are in the decision file of each format.

## Deliberate decisions (do not revert)

| Decision | Why | Pinned by |
| --- | --- | --- |
| When the image limit is exceeded, scanned pages come first. A page image left out by the limit is warned about apart from the pictures, with its page numbers ('… were left out and are empty'); only the pictures are counted as 'left as placeholders only' | A page image is the only content of that page. Counted with the pictures, the warning said every image left out kept a placeholder, and the pages left empty were named nowhere | `test_image.py::TestScannedPagesLeftOutByTheImageLimit` |
| `max_images` defaults to unlimited (None) | Real Hangul (HWP) documents had 51 and 32 pictures, more than the former default of 30, and content was lost. Only a caller that wants to bound cost sets a limit | `test_image.py::test_describes_every_image_by_default` |
| The ChatOpenAI the describer builds itself is separate per event loop (its own httpx client), and `aclose()` closes that loop's client before the loop ends (the CLI calls it) | langchain_openai's global client is bound to the first loop, so from the second asyncio.run on: "Event loop is closed" | `test_image.py::test_openai_describer_uses_separate_http_client_per_event_loop`, `test_openai_describer_closes_the_http_client_of_the_current_event_loop` |
| SKIP is forbidden when there is even one character of text (prompt) | gpt-4o-mini erased text pictures such as "FIG 4411" as decorative 3 times out of 3 | live test against the real model (not in this repository) `test_text_figure_is_kept_but_pure_decoration_is_dropped` |
| A "no information" answer (SKIP, illegible, a short "it is empty" claim) gets one more confirmation query that only transcribes the text; decorative only when both say nothing. The confirmation answer replaces the first one only when the first answer was no-information or shares no word with the confirmation answer; when they overlap the first answer is kept (new text only is appended, `describe._merge_second_look`) | The real gpt-4o-mini answered "(illegible)" (~1/3) and "empty image" (~1/12) for crisp text pictures. Trusting the first answer alone loses content. Replacing wholesale turned a chart summary with a single illegible value into a list of characters | `test_image.py::TestNoContentSecondOpinion`, `test_skip_answer_variants_count_as_decorative` |
| Filtering of small and thin pictures applies only to pictures inside documents | A 4208×180 banner uploaded by the user was discarded whole | `test_image.py::test_wide_uploaded_image_is_not_dropped_as_separator` |
| Thin (aspect ratio over 20:1) only counts when the short side is under 256px (`image._CONTENT_SHORT_SIDE`). For a picture whose long side is over 4× the short side and over twice `image_max_side`, tiles cut along the long side are made in addition to the downscaled whole (`data`) (`DocumentImage.tiles` — twice the short side long, up to 8, overlapping neighbours by 1/16), and `OpenAIImageDescriber` sends the tiles in order in a single query (note text `describe._TILES_NOTE`). A describer that does not know about tiles sees only `data` as before | Product-detail pages inside documents (860×18000) and long screen captures were discarded as separators, and uploaded pictures were shrunk to 98×2048 so the text was unreadable (tiles are about 700×2048). Tiles are not registered as separate pictures, to keep one picture = one description = one placeholder. **The tile query was verified with a fake model only (not run against the real model)** | `test_core_image_and_assembly.py::TestTallPictures`, `test_image.py::TestPrepareImage::test_skips_tiny_icon_and_thin_separator` |
| PNGs of transparent pictures are rewritten with default compression, without `optimize` (`image._encoded`). JPEG `optimize` stays | The search for a compression level took most of the conversion time of picture-heavy PPTX/HWP (122-picture deck 31.7 s → 3.5 s, HWP with 51 pictures 7.0 s → 0.5 s). The result size even shrank a little | `test_core_round47.py::TestTransparentPictureEncoding` |
| A failure to decode, downscale or re-encode an image is `ImageUnreadable` whatever the exception type, with one exception: a `MemoryError` goes up as it is (`image.prepare_image`), and the converter makes it a `DocumentTooLargeError` with `TOO_COMPLEX_MESSAGE` (the memory overrun of [core.md](core.md)). 16-bit grayscale is converted to 8-bit and downscaled; 32-bit integer/float (I, F) grayscale has the picture's minimum–maximum stretched to 0–255 (`image._stretch_to_8bit`; preserves contrast, not the original brightness) | Pillow raised SyntaxError for a corrupted PNG and ValueError when downscaling 16-bit grayscale, leaking out past ConversionError. Running out of memory under a worker's limit was taken for a broken picture: an uploaded photo was 'corrupted' and a picture in a document a format warning, never 'too large or too complex'. A float 0–1 TIFF became all black and integer 0–65535 nearly white | `test_image.py::test_broken_png_is_unreadable_not_a_crash`, `test_high_bit_depth_grayscale_is_converted_not_a_crash`, `TestAuditedImageGaps::test_wide_range_grayscale_keeps_its_gradient`, `TestOutOfMemoryWhileReadingAPicture` |
| A failed description is kept in `DocumentImage.failed` and the warning is computed by `render` every time | Warnings accumulated in `base_warnings` remain even after a retry succeeds. Calling again calls only for the failed ones | `test_image.py::test_describing_again_retries_only_failed_images_and_clears_warning` |
| The default vision model is in one place, `describe.DEFAULT_MODEL`. Tests, samples and the CLI do not hard-code a model name | gpt-4o-mini made up numbers in dense scans, and gpt-4.1-mini and gpt-4o made up characters they could not read (table in [design.md](../design.md)). When it changes, the real-model checks and samples are run again. "gpt-4o-mini did …" in these tables is a record of what was observed at the time and is not edited | — (checked against the real model) |
| No numbers or years in the examples of the prompt | "2024~2026년" from an example leaked into chart summaries | live test against the real model (not in this repository) `test_docx_places_chart_between_paragraphs_and_cell_image_in_row` |
| The same source picture is decoded only once in `_prepare_images`, and the body text before a picture is gathered carrying only its tail | It took picture count × body length (19 s for 16,384 pictures) | `test_image.py::test_same_picture_is_decoded_once` |
| For the same picture appearing again below the repetition threshold (`repeated_image_threshold`), the placeholder in the section source is replaced by the number of the first one (`_point_aliases_at_first`): described once, the same description or fallback text at every position. The context is that of the first position, the alt text that of the first one (a later one if it has none). At or above the threshold it is taken for a logo and erased (as before) | The second position disappeared entirely from the body and the sections. For the limit verdict the existing upper bound, which multiplies by the number of placeholder occurrences, still holds | `test_image.py::TestSamePictureTwice` |
| Even with a decorative (SKIP) verdict, `[Image: alt text]` is kept when there is author-written alt text (`converter._erased`). Pictures filtered by size and repeated logos are erased regardless of alt text | Information written by a person disappeared on a single verdict of the describer | `test_image.py::TestDecorativePictureWithAltText` |
| A `CancelledError` raised by the describer itself is a failure of that picture (`failed`). It is re-raised only when this task was cancelled (`current_task().cancelling()`) | The outside had not been cancelled, yet the whole aconvert died and the descriptions of the other pictures were lost | `test_image.py::TestAuditedImageGaps::test_describer_that_raises_cancelled_error_itself_fails_only_that_image`, `test_cancelling_aconvert_still_cancels_it` |
| With `extract_images=False` a standalone uploaded image is not read either (no decoding, no description), with one warning | The README says "ignored completely", yet standalone images were sent to the describer | `test_image.py::TestAuditedImageGaps::test_extract_images_off_does_not_send_an_uploaded_image_to_the_describer` |
| The image placeholder is `⟦IMG:<first 16 characters of the file hash>:n⟧` (`models.marker_key`); the key is carried in the result | A `⟦IMG:1⟧` written as text in the body was erased and the picture inserted twice | `test_converter.py::TestAssembly::test_text_that_looks_like_an_image_placeholder_is_kept_as_text` |
| The limit verdict during description subtracts `converter.image_length_bound` (at least the real increase) from the headroom and assembles only when it runs out. A picture that is erased (decorative, no alt text) has a bound of 0 — the floor erases it already | Assembling for every picture took 25 s for 3,332 pictures. With 3 characters counted for every SKIP answer, a document just under the limit was assembled again every few pictures: 2,000 pictures took 2.6 s and 10,000 blocked the event loop for 245 s | `test_image.py::TestResourceBounds::test_description_stops_at_exactly_the_image_that_crosses_the_limit` and 1 more, `test_core_image_and_assembly.py::TestDecorativeAnswersNearTheLimit` |
| In cells repeated for a vertical merge the picture placeholder is left out and only the text is repeated (picture in the top cell only). As a safety net the upper bound on the increase during description is multiplied by the number of placeholder occurrences | The picture description went in once per row, inflating the character count and delaying the limit verdict | `test_markdown.py::TestTableGrid::test_vertical_merge_repeats_text_but_not_image_placeholder`, `test_image.py::TestResourceBounds::test_description_stops_at_the_same_image_when_a_placeholder_appears_more_than_once` |
| A picture block inside a paragraph is followed by a blank line, and the line the placeholder was taken from keeps its indentation (`image_length_bound` +3) | The next line ran on into the quote block and a sub-list item moved up to the top level | `test_converter.py::TestAssembly::test_picture_block_inside_a_paragraph_is_followed_by_a_blank_line`, `test_picture_in_nested_list_item_keeps_the_item_indentation` |
| A standalone uploaded image that cannot be decoded is a `CorruptedDocumentError`; an empty answer from the describer is `failed` (warning, retry); undecodable pictures inside a document (WMF, EMF etc.) give a count warning. A describer answer that is a list of text pieces is joined, and one that is not text fails only that picture. BMP is detected by 'BM' + the DIB header size | A result of nothing but '[Image]' succeeded without a warning, the AttributeError of a list answer killed the whole batch, and a BMP with bfSize 0 was rejected | `test_image.py::TestStandaloneImage`, `TestDocxImages::test_unreadable_picture_in_a_document_is_reported_in_warnings`, `TestDescribeImages::test_describer_answer_that_is_not_text_fails_only_that_image` |
| Office auto-generated alt text (ending in '자동 생성된 설명', 'Description automatically generated', 'AI 생성/AI가 생성한 콘텐츠는…', 'AI-generated content…', or a single line without that tail of the form '낱말, 낱말이(가) 표시된 사진/그림' ("a photo/picture showing word, word"), 'A picture containing lowercase word, …') is discarded through `_USELESS_ALT`. Text with an added line, or that is a sentence, is kept | It went to the describer as author alt text and stayed in the body even after a decorative verdict. Matching broadly also erased human text ('A picture containing our CEO …') | `test_image.py::TestOfficeAutoGeneratedAltText` |
| A completely empty answer from the describer (`""`, None, fences only) and SKIP-like answers for scanned pages (PAGE) and uploaded pictures (STANDALONE) are `failed` (warning, eligible for retry). Only SKIP-like answers for FIGURE are decorative. The confirmation query of `OpenAIImageDescriber` follows the same rule: when the confirmation answer is empty, or the first answer is empty and the confirmation answer is NONE, it returns an empty answer and fails (SKIP only when both answers said 'no text') | An empty answer was treated as decorative and the picture disappeared without a warning; for PAGE and STANDALONE the text 'SKIP' became the body. Two empty answers became SKIP through `is_no_content("")` | `test_image.py::TestDescribeImages::test_completely_empty_answer_for_a_figure_is_a_failure_not_a_decoration`, `TestNoContentSecondOpinion::test_empty_answer_in_either_pass_is_a_failure_not_a_decoration`, `test_skip_answer_for_an_uploaded_image_is_a_failure`, `test_skip_answer_for_a_scanned_page_is_a_failure` |
| For a JPEG over the decoded-pixel limit (`image._MAX_DECODE_PIXELS`, about 179 million = Pillow's decompression-bomb limit) the decoder is opened directly (bypassing the limit check of `Image.open`; the global `MAX_IMAGE_PIXELS` is untouched) and draft-decoded at the smallest reduction that fits the limit (1/2, 1/4, 1/8; reduced further when the long side is at least `image_max_side`). When even 1/8 is over, or it is not a JPEG, it is `ImageTooLarge`: an uploaded picture is a `DocumentTooLargeError`, a picture inside a document gets the fallback text + a 'too large' count warning (separate from the undecodable warning, `image._open_within_pixel_limit`) | Panoramas and large scans (16000×12000 etc.) were rejected as a 'corrupted image'. JPEG is decoded reduced at the DCT stage, so memory stays within the limit (192-megapixel JPEG in 0.09 s). Other formats have to be decoded whole, so they are not read. A large picture inside a document was reported as 'a WMF/EMF vector or the like, or corrupted' | `test_core_image_and_assembly.py::TestVeryLargePictures`, `test_core_mbox_markdown_and_api.py::TestTooLargePictureInsideADocument` |
| A JPEG truncated at the end (there is picture data after SOS and no end marker EOI) is decoded again with EOI appended (`image._truncated_jpeg`). The decoder fills the remaining lines with gray. When the height actually drawn (the last line that differs from the fill colour at the bottom right) is under 10% of the whole (`_MIN_TRUNCATED_JPEG_SHARE`), it is undecodable as before. No warning (how much was cut cannot be known, and only the visible part is described). The global `ImageFile.LOAD_TRUNCATED_IMAGES` is not used | A photo missing only the 2 EOI bytes was rejected as 'corrupted' as a standalone upload and became the fallback text inside a document — a browser shows such a picture. The global setting spreads to other conversions and libraries in the process | `test_core_round45.py::TestSlightlyTruncatedJpeg` |
| A progressive JPEG over `image._MAX_DECODE_PIXELS` is `ImageTooLarge`; only baseline JPEGs are draft-decoded | The progressive decoder keeps the coefficients of the whole picture whatever the reduction: 20000×20000 (1.5 MB on disk) peaked at 946 MB against 148 MB for baseline | `test_audit_runtime.py::TestProgressiveJpegOverThePixelLimit` |
| Pictures are opened with an explicit list of raster formats decoded in this process (`image._OPEN_FORMATS`); EPS, WMF / EMF and stub or container plugins are never tried | `Image.open` tries every plugin: an EPS inside a document reached the PostScript plugin, which starts Ghostscript on untrusted input | `test_audit_runtime.py::TestPictureFormatAllowList` |
| Pillow's warnings (`UserWarning` and `DecompressionBombWarning` from its modules) are silenced while a picture is decoded and re-encoded, as while a multi-page TIFF is split (`image._PILLOW_WARNINGS`, through the thread-safe `models.quiet_warnings`) | A warning about a tag of the wrong count leaked out of the single-picture path: with warnings turned into errors a readable picture was rejected as 'corrupted' or left as placeholder text. What counts is the outcome, read or `ImageUnreadable` | `test_image.py::TestPillowWarnings` |
| A picture is kept transparent (PNG) when it has any alpha band (RGBA, LA, PA, RGBa, La) or a `transparency` entry (palette, or the tRNS level or colour of an L or RGB PNG) | Only RGBA, LA and P were looked at: a PA TIFF became a JPEG with a black background | `test_image.py::TestTransparencyOfEveryMode` |
