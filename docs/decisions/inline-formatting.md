# Links and emphasis decisions

Deliberate decisions for keeping hyperlinks (`[text](url)`) and bold / italic (`**bold**`, `*italic*`, `***both***`) in DOCX, PPTX and HTML (`ConvertOptions.keep_links`, `keep_emphasis`; both on by default). The rules live in one place, `extractors/_shared.py` (`link_target`, `resolve_inline`); the extractors only say where a span starts and ends.
The rule is the same as in the other files: do not revert the decisions in this table. To change one, change its pinning test first and write the reason in the same row.

| Decision | Why | Pinned by |
| --- | --- | --- |
| With `keep_links` and `keep_emphasis` both off, the three extractors take the path they took before the options existed (DOCX `_Inline` is None, PPTX `_inline_of` is None, HTML `_inline` is None): no marks are put into the text and nothing is resolved | The options were added to a published library; a caller who switches them off must get the old output byte for byte. Output, warnings and limit verdicts of 180 real DOCX / PPTX / HTML / mail files were identical to the previous release with the options off | `test_inline_formatting.py::TestDocxLinks::test_links_off_gives_the_text_only`, `TestDocxEmphasis::test_emphasis_off_gives_the_text_only`, `TestPptx::test_options_off_give_the_text_only`, `TestHtmlLinks::test_links_off_gives_the_text_only`, `TestHtmlEmphasis::test_emphasis_off_gives_the_text_only` |
| Only `http`, `https` and `mailto` addresses become links (`_shared.link_target`, scheme compared without case). Relative addresses, `#fragment`, protocol-relative `//host`, `javascript:`, `file:`, `data:`, `ftp:`, `tel:` and empty addresses stay plain text. Nothing is resolved against a base address and nothing is fetched | A saved page or a document has no base address, so a relative link points nowhere; a script, file or data address must not become something the reader of the Markdown can follow. `convert` stays offline | `test_inline_formatting.py::TestLinkTargets`, `TestHtmlLinks::test_absolute_link_is_kept_and_other_addresses_stay_text`, `TestDocxLinks::test_external_relationship_to_something_other_than_a_web_address_stays_text` |
| Characters of an address that would end the link, split a table row or be changed by `clean_text` are percent-encoded: whitespace of every kind, control characters, `( ) < > \| \` and the brackets of a picture placeholder (`_LINK_UNSAFE`). Other characters, Korean included, stay readable | `)` closes the link, a space ends the address, `\|` splits a Markdown table row, a backslash escapes what follows, and `clean_text` turns a non-breaking space into a space. An address such as `https://a/x) [y](https://evil/` wrote a second link | `test_inline_formatting.py::TestLinkTargets::test_characters_that_would_break_the_markdown_are_percent_encoded`, `test_korean_address_is_kept_readable`, `TestHtmlLinks::test_address_cannot_close_the_link_or_split_a_table_row` |
| In link text, a `]` without its `[`, a `[` without its `]`, and a bracket pair followed by `(` or `[` are escaped with a backslash; other balanced brackets stay (`[Image: logo]`, `[1]`). A lone backslash at the end of the text is doubled (`_escape_link_text`) | Link text `여기](https://evil.example) [x` closed the link early and opened another one whose address the document chose as text. Escaping every bracket would turn `[Image: logo]` and `[1]` into `\[…\]` in every linked picture and citation | `test_inline_formatting.py::TestLinkTargets::test_text_that_closes_the_link_cannot_point_it_somewhere_else`, `test_a_link_written_out_inside_link_text_is_escaped`, `test_balanced_brackets_in_link_text_stay`, `test_backslash_at_the_end_of_link_text_does_not_escape_the_bracket` |
| A link whose text is its own address stays the bare address (also `team@example.com` linked to `mailto:team@example.com`, and a difference of only a trailing `/`). `<url>` autolinks are not used | `[https://a.example](https://a.example)` says the same thing twice, and the bare address is exactly the old output. `<https://…>` inside an HTML table cell reads as an unknown tag | `test_inline_formatting.py::TestDocxLinks::test_link_whose_text_is_its_address_stays_the_bare_address`, `TestHtmlLinks::test_link_whose_text_is_its_address_stays_the_bare_address` |
| A picture placeholder, `[Image: alt]`, `[OLE object]`, `[Chart]`, `[Video]` and a footnote reference are never emphasized, and at the edge of a link they stay outside the brackets. A link with nothing but a placeholder inside is not written — the placeholder stays, the address is dropped | The converter turns a picture placeholder into a block below its line, which would leave `[](url)` and `****` behind. Known accepted gap: the address of a linked picture is lost | `test_inline_formatting.py::TestDocxLinks::test_link_around_a_picture_keeps_the_picture_and_writes_no_link`, `test_picture_at_the_edge_of_a_link_stays_outside_the_brackets`, `TestHtmlLinks::test_link_around_a_picture_keeps_the_placeholder`, `TestResolver::test_placeholders_are_not_emphasized` |
| DOCX links: `w:hyperlink` whose `r:id` is an external relationship of the part being read (body, header, footnote part — `_DocxRenderer._hyperlink_target`), with `w:anchor` appended as the fragment; and HYPERLINK fields (complex field and `w:fldSimple`, `docx._field_link`). A `w:hyperlink` with only `w:anchor`, `HYPERLINK \l "bookmark"`, an internal or missing relationship stay text. A field that never ends leaves no link. PPTX links: `a:hlinkClick` in `a:rPr` with an external relationship of the slide; runs that follow each other with the same address are one link; slide jumps (`ppaction://…`) stay text | Tables of contents and cross-references are jumps inside the document and have no address. Looking the id up in the body part would take another part's relationship (same reason as header pictures in [office.md](office.md)). PowerPoint puts the link on every run | `test_inline_formatting.py::TestDocxLinks` (`test_hyperlink_field_code_is_a_link`, `test_simple_hyperlink_field_is_a_link`, `test_hyperlink_field_to_a_bookmark_or_without_an_end_stays_text`, `test_jump_inside_the_document_and_a_broken_relationship_stay_text`, `test_link_in_a_footnote_uses_the_relationships_of_the_footnote_part`, `test_bookmark_is_appended_as_the_fragment`), `TestPptx::test_runs_of_one_link_are_one_link_and_bold_inside_it_is_kept`, `test_bold_set_to_false_and_a_jump_to_another_slide_are_plain` |
| DOCX emphasis is read from `w:b` / `w:i` set directly on the run (`w:val="0"`, `false`, `off` switch it off) and from the character styles named Strong and Emphasis (`docx._run_emphasis`). The paragraph style, other character styles, the document defaults and complex-script bold (`w:bCs`, `w:iCs`) are not followed. PPTX: `a:rPr` `b` / `i` of the run only (not the placeholder or list style). HTML: `<b>`, `<strong>`, `<i>`, `<em>` only — not `<cite>`, `<var>`, `<dfn>`, CSS `font-weight` / `font-style` | A heading, title or label style is bold as a whole: that says what the paragraph is, not that its words are stressed, and following styles would mark whole documents whose body style is bold. Known accepted gap: bold that comes only from another character style or from CSS is not marked | `test_inline_formatting.py::TestDocxEmphasis::test_value_zero_or_false_switches_the_emphasis_off`, `test_strong_and_emphasis_character_styles_are_emphasis`, `test_boldness_of_a_paragraph_style_is_not_emphasis`, `TestHtmlEmphasis::test_cite_var_and_css_weight_are_not_emphasis` |
| No emphasis in headings (DOCX heading / title styles and outline levels, HTML `h1`–`h6`), in HTML table captions, in PPTX slide titles, and inside HTML `<pre>`, `<code>`, `<kbd>`, `<samp>`, `<tt>`. Links are kept in headings and captions. PPTX slide titles and speaker notes are read as plain text (no link either — known accepted gap), and so are DOCX comments, shape text pasted from PowerPoint and WordArt | `# **제목**` is noise: a heading is bold by style, and a title typed in bold is still a title. In code `*` is a character of the code | `test_inline_formatting.py::TestDocxEmphasis::test_heading_is_not_emphasized`, `TestHtmlEmphasis::test_heading_and_caption_are_not_emphasized`, `test_code_is_not_emphasized`, `TestPptx::test_slide_title_stays_plain`, `TestDocxLinks::test_link_in_a_heading_a_list_item_and_a_table_cell` |
| Bold (or italic) that covers a whole block from its first to its last word is not written (`_shared._drop_uniform_emphasis`). A block is a DOCX or PPTX paragraph (also each paragraph of a table cell and each list item) and, in HTML, the text between two blank lines of what is being rendered (a paragraph, a list item, a table cell). A bullet or number at the start, whitespace and placeholders are not counted as words. This covers header cells and label cells of tables. **Wider than first specified (table cells only), on purpose** | Bold over a whole paragraph is how the paragraph is styled — a label, a header cell, a slide caption — not a stress inside it. Marked, 5,939 of the 7,777 marked lines in 143 real DOCX / PPTX files were whole lines in `**…**`: about a quarter of all lines of slide decks and 13–17% more characters, with every caption box and form label in bold. Known accepted gap: a line that is a heading only by being bold (`**1. 개요**`) is not marked as one — as before the options existed | `test_inline_formatting.py::TestWholeBlocks`, `TestPptx::test_caption_that_is_bold_throughout_is_not_marked`, `TestHtmlEmphasis::test_cell_that_is_bold_throughout_is_not_marked_and_rows_stay_whole`, `test_paragraph_and_list_item_that_are_bold_throughout_are_not_marked` |
| Emphasis that starts in the middle of a word, and a single emphasized character glued to the rest of its word, are not written (`_shared._drop_emphasis_inside_words`). A span that starts a word and stops before its ending **is** written: `**매출**은`, `*배출*량` | `1<b>2</b>,345`, `인사<em>발령</em>` and `<b>부</b>분` are styling of part of a word (a digit in another weight, a decorated initial) and came out as `1**2**,345`, `인사*발령*`, `**부**분`. But in Korean the particle is written onto the stressed word without a space, and most emphasis in real documents has that shape (`**신규 요금제**를`, `**A사**가`) — requiring a word boundary on both sides would drop it. Known accepted gap: an emphasized one-syllable word before a particle (`<b>값</b>이`) and a stressed initial (`<b>S</b>trength`) are not marked | `test_inline_formatting.py::TestPartOfAWord` |
| Neighbouring runs with the same formatting are one span, also across whitespace-only runs; whitespace goes outside the marks; whitespace-only runs are not marked; bold is the outer mark and italic the inner one (`**a *b* c**`); emphasis stops at the edge of a link (`**앞** [**링크**](url)`) | Word splits a sentence into runs at every spelling mark, giving `**매****출**`; `** 굵게 **` is not emphasis in Markdown; a span that crosses a link edge (`**앞 [링크**](url)`) is neither | `test_inline_formatting.py::TestDocxEmphasis::test_runs_with_the_same_formatting_are_one_span`, `test_whitespace_stays_outside_the_marks`, `test_bold_inside_italic_and_the_other_way_round_nest`, `TestResolver::test_emphasis_stops_at_the_edge_of_a_link`, `TestDocxLinks::test_link_split_into_several_runs_is_one_link` |
| A span is closed and reopened at a line break, and a bullet or number at the start of a line stays in front of the marks (`- **항목**`, `1. **개요**`; `_INLINE_LEAD`). After a heading mark (`#`) the line is not emphasized | `**- 항목**` is not a list item, and the extractors look for hand-typed bullets at the start of a line (DOCX `_list_item_lines`, PPTX `_item_lines`) | `test_inline_formatting.py::TestDocxEmphasis::test_line_break_closes_and_reopens_the_span_and_a_bullet_stays_in_front`, `TestWholeBlocks::test_list_item_and_numbered_line_keep_their_marker_in_front`, `TestHtmlEmphasis::test_line_break_closes_and_reopens_the_span` |
| A span whose words are in different blocks is not written — a blank line between them, or (HTML) a table, list, code block, quote block or definition list rendered inside it (`_shared.BLOCK_INSIDE`). A span around exactly one block is written inside that block (`<a><h3>제목</h3></a>` → `### [제목](url)`). An HTML span does not reach into tables, lists and code blocks, which are rendered on their own | Markdown links and emphasis cannot hold a blank line. An unclosed `<b>` wraps the rest of the page, and marking every paragraph after it is the same noise as whole-line bold. Card layouts wrap the heading in the link. Known accepted gap: the address of a link around several blocks is lost | `test_inline_formatting.py::TestHtmlLinks::test_link_around_one_heading_is_written_inside_the_heading`, `test_link_around_several_blocks_or_a_table_stays_text`, `TestHtmlEmphasis::test_unclosed_bold_element_does_not_mark_the_rest_of_the_page`, `test_emphasis_around_a_single_paragraph_marks_nothing_but_words_inside_it`, `TestResolver::test_span_with_words_in_two_blocks_is_not_written`, `test_block_rendered_on_its_own_breaks_the_span_around_it` |
| A literal `*` at the edge of an emphasized span and a lone backslash at its end are escaped with a backslash (`_shared._guard`). Known accepted gaps: `*` and `_` elsewhere in the text are not escaped (text such as `*주의*` typed in a document reads as emphasis, as it did before); a span that ends in punctuation directly followed by a letter (`**요금제(월간)**에`) is not a closing mark for a strict CommonMark renderer, which then shows the asterisks; `_` next to a mark is left alone (it cannot join a `*` mark) | `**주의***` is read as a longer mark and `**C:\dir\**` as an escaped asterisk. The output is read by an LLM, which reads `**…**에` as emphasis; moving the punctuation out of the span or dropping the emphasis would change or lose what the author stressed | `test_inline_formatting.py::TestDocxEmphasis::test_literal_asterisk_or_backslash_at_the_edge_of_a_span_is_escaped` |
| Strikethrough is the inner notation and emphasis the outer one (`**~~1,000~~**`); a superscript or subscript run stays part of the bold span around it (`**H_2O**`: the emphasis mark is put around the script mark). In HTML, where `~~` is written into the text first, a span that holds only one half of a `~~` pair at its edge leaves that half outside (`~~이전 **가격**~~`); a span crossed by `~~` in its middle is left unmarked (`_shared._without_edge_strike`) | The marks must close in the order they opened: `~~구 **판~~**` is neither strikethrough nor bold. `**H**_2**O**` split one formula into three spans | `test_inline_formatting.py::TestDocxEmphasis::test_strikethrough_superscript_footnote_and_picture_inside_bold_text`, `TestHtmlEmphasis::test_strikethrough_and_emphasis_nest` |
| DOCX and PPTX announce a span with control characters inside the run text (U+000E–U+0014, which XML text cannot hold and `str.split` does not treat as whitespace), resolved after the strikethrough and script marks. HTML never uses them: it puts `InlineMark` objects between the pieces of text, and the document tree is not changed | HTML text can hold those characters (`&#18;`), so marks inside the text could be forged into a link the page never had. Leaving the tree alone keeps every decision that measures an element's text (layout tables, name cells, folded answers) exactly as it was | `test_inline_formatting.py::TestHtmlLinks::test_control_characters_in_the_page_cannot_forge_a_link` |
| Character limit: the marks and addresses are part of the text and count. DOCX and PPTX decide what a paragraph is and write its Markdown before anything is counted, so `Extraction.count` and `TableBudget` see exactly what lands in the result (bold dropped from a whole cell is not counted). The front-part verdict of a large HTML page (`html._extract_front`) counts without the link addresses and brackets (`_LINK_ADDRESS`, `_LINK_BRACKETS`; `*` and `\` were already left out), and a link that may be cut at the end of the front part stays text there (`_Inline.cut`) | `exceeded` must equal "the full conversion is longer than `max_chars`" ([core.md](core.md)). A heading cut at the end of the front part holds links there but is read as text only in the whole page when it turns out to hold a list; counting its addresses stopped a page that is within the limit. 2,359 limit verdicts on 169 real DOCX / PPTX / HTML files and over 9,000 on random HTML with links and emphasis: 0 mismatches | `test_inline_formatting.py::TestCharacterLimit` |
| Everything is resolved in one pass over the pieces of a paragraph or frame: validity of nested spans is settled in the order they opened, blocks are walked by index, and unformatted lines between two line breaks stay one piece | Slicing the list for every block made a page of 40,000 short blocks quadratic (16.8 s → 1.6 s); an unclosed `<b>` is nested once per occurrence by the parser | `test_inline_formatting.py::TestLinearTime` |
| `<title>` is looked for in the first line of the body without the emphasis marks before it is put in front as a heading (`html._with_title_heading`) | `**주간** 보고` in the first line no longer contained the title `주간 보고`, so the title was stacked on top of it | `test_inline_formatting.py::TestHtmlEmphasis::test_title_is_found_in_a_first_line_that_carries_marks` |
