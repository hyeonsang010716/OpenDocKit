# Office chart decisions

Deliberate decisions for OOXML charts (`_shared.render_chart`, `render_chartex` — PPTX, DOCX, HWPX; charts on Excel sheets use the same functions). Split off from [office.md](office.md);
the rule is the same: do not revert the decisions in this table. To change one, change its pinning test first and write the reason in the same row.
Charts inside a table cell (`embedded_table`) are in [office.md](office.md), charts placed on an Excel sheet in [spreadsheet.md](spreadsheet.md).

## Charts

| Decision | Why | Pinned by |
| --- | --- | --- |
| PPTX chart values keep all their digits | `:g` cut at 6 digits | `test_office.py::TestPptx::test_chart_values_keep_all_their_digits` |
| OOXML charts are read directly from the chart XML with `_shared.render_chart`, not through python-pptx chart objects (shared by PPTX, DOCX, HWPX). Every chart of the plot area is merged per category; scatter and bubble charts give X/Y pairs per series | Only the first chart was read, so combo series were missing; scatter charts had 0 value rows; DOCX and HWPX charts were dropped whole | `test_office.py::TestPptx::test_scatter_chart_values_are_kept`, `test_combo_chart_keeps_series_of_every_plot`, `TestDocxObjects::test_chart_and_smartart_are_kept`, `test_hwp.py::TestHwpxObjects::test_chart_data_is_kept` |
| Chart axis titles are one line below the title (`Category axis: … / Value axis: …`; X/Y when there are only value axes), and below that the paragraphs of text boxes inside the chart (c:userShapes → the drawing part of the chart part's relationships), one line each (`load_related` of `render_chart`: `related_loader` for DOCX/PPTX, `package_loader` for HWPX and XLSX sheet charts). A numeric category becomes an ISO date when its format is a date (1904 system and dateAx format respected; `YYYY-MM` for a format without day (d) or weekday, `YYYY` for year only — same as Excel cell dates), otherwise it is tidied like a value | The unit was only in the axis title or a text box ('(단위: 억원)', unit: 100 million KRW), and date categories went out as the serial number 46023.0 | `test_office.py::TestChartAxes`, `test_office_chart_units_and_ole.py::TestChartUserShapes`, `test_core_spreadsheet.py::TestSheetChartUserShapes` |
| The new chart kinds (chartex: waterfall, treemap etc.) become a value table through `_shared.render_chartex`; when unreadable, the mc:Fallback picture; without that either, `[Chart]`. **Followed the schema only, without a real chartex sample (unverified)** | Choice was taken for a known shape and the Fallback picture discarded, so it disappeared without a trace | `test_chartex_*` in `test_office.py::TestPptxLayoutAndEmbeddedObjects`, `TestDocxFieldsAndRuns` |
| Multi-level chart categories (c:multiLvlStrRef) join the levels from outer → inner with a space (`2024 상반기`). A value of an outer level continues until the next value appears. chartex uses the inner level only | Only the inner level was read, so nobody could tell which year '상반기' (first half) and '하반기' (second half) belonged to | `test_office.py::TestChartAxes::test_multi_level_categories_join_the_outer_levels` |
| A chart value is `25.3%` when the cached format (c:formatCode; the formatCode of c:pt when it differs per point) is a percentage (decimal places as in the format), and `1,200억원` when it is a simple number format with a literal unit attached (`#,##0"억원"`, `"₩"#,##0`, `[$₩-412]#,##0`, `#,##0,"천원"`, an escaped `%`) (digit grouping, division by thousands for a trailing `,`, decimal places, the second section for negatives; `_shared._format_units`). With formats without a literal unit (rounding would only lose value), conditions, dates, exponents and text formats the value stays as is | 0.253 of a pie chart was not read as 25.3%, and the unit that exists only in the format was missing, so nobody knew what 1200 was | `test_office.py::TestChartAxes::test_values_with_a_percent_format_are_shown_as_percentages`, `test_point_level_percent_format_applies_to_that_point_only`, `test_office_chart_units_and_ole.py::TestChartValueUnits` |
| When the second section of a chart value format has no character showing it is negative (its literals equal the first section's or the section is empty — `#,##0"억원";[Red]#,##0"억원"`), `-` is prefixed (`_shared._format_units` — the same rule as `spreadsheet._format_section` for Excel cells). A section that shows the negative, such as `(…)`, `△` or `-`, is used as it is | The colour is discarded, so -300 went out as `300억원` and a loss read as a profit | `test_office_chart_units_and_ole.py::TestChartNegativeSectionWithoutSign` |
| Only when the cached value format of a category-axis chart is General (or absent), the format of the visible data labels (c:dLbls — the series' own, else the chart's; showVal true) is used, or else the format of the visible value axis (c:valAx, found through the chart's c:axId) (`_shared._shown_value_format`). Not used: a format that follows the source cell format (sourceLinked), deleted labels, deleted axes, and the value-axis format of a 100% stacked chart (grouping percentStacked) (the scale of cumulative shares — 1200 would become 120000%). Deliberate: when the cached format is not General it is the source cell format and takes precedence. Does not apply to scatter and bubble charts | In a chart whose unit is only in the label or axis format, 1200 came out without a unit | `test_office_chart_units_and_ole.py::TestChartUnitsOnLabelsAndValueAxis` |
| A line break inside a DrawingML paragraph (a:br) is a line break (`_shared.drawing_paragraph_lines`): where a single line is written (SmartArt items, cx:tx titles of the new charts — as in `_title_text`) the lines are joined with a space, and where each line becomes a block (text boxes in a chart c:userShapes, shape text pasted into DOCX `docx._drawing_lines`) the lines are split. The same rule as XLSX text boxes (`spreadsheet._text_body`) and PPTX text boxes | Joining only the a:t made SmartArt '2023' + a:br + '1,500' into '20231,500', and '1단계' + '기반 구축' into '1단계기반 구축' | `test_office_drawing_line_breaks.py::TestLineBreaksInsideDrawingParagraphs` |
