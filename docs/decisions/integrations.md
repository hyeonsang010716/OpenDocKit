# Integration decisions (LangChain, LlamaIndex, MCP)

Deliberate decisions of `opendockit.integrations` and `opendockit.mcp_server`. The rule is the same as in [extractors.md](extractors.md): do not revert the decisions in this table. To change one, change its pinning test first and write the reason here.

| Decision | Why | Pinned by |
| --- | --- | --- |
| The adapters live in this package behind extras (`langchain`, `llamaindex`, `mcp`), not in separate distributions. Nothing in `opendockit` imports them, and each module fails on import with the install command when its framework is missing | One version, one release and one test run cover the converter and its adapters; a separate package per framework would be three more things to keep in step for about fifty lines each. The price: the adapters are not named the way the frameworks' own catalogues expect (`langchain-…`, `llama-index-readers-…`) | `test_integrations.py`, `test_mcp_server.py` (skipped when the extra is missing) |
| One function (`integrations._documents.pieces`) decides how a result is cut and what its metadata is, for every adapter | An index built with LangChain and one built with LlamaIndex must cite the same page for the same passage | `test_integrations.py::TestLlamaIndexReader::test_load_data_gives_documents_with_the_same_pieces_as_the_loader` |
| `mode="sections"` gives one piece per page, slide or sheet; a document without physical units is one piece in either mode. The adapters do not split by headings or by size | Pages, slides and sheets are facts of the file and the unit people cite. How to chunk prose is the caller's choice, and the frameworks already have Markdown splitters | `TestLangChainLoader::test_sections_mode_gives_a_document_per_sheet_slide_and_page`, `test_document_without_units_is_one_piece_in_either_mode` |
| A piece of a slide or sheet starts with the heading of the full text (`converter.section_heading`); a page carries no `<!-- Page N -->` marker | A sheet read alone without its name, or a slide without its title, has lost the one line that says what the numbers are. A page number is not content: it is `section_index` | same test |
| Metadata values are strings, integers and booleans only: warnings are one string with a line each, and `warnings` / `exceeded` are absent when there is nothing to say | Chroma, Pinecone and others reject lists and nested values in metadata, and the failure appears only when the documents are stored | `TestLangChainLoader::test_metadata_values_are_plain_scalars` |
| A file that cannot be converted raises the converter's `ConversionError`; the loader has no "skip errors" switch. `lazy_load` converts a file only when it is reached | A document missing from an index without a word is the failure nobody notices. The caller who wants to skip can catch the exception around `lazy_load` | `test_file_that_cannot_be_converted_raises_the_conversion_error`, `test_lazy_load_converts_a_file_only_when_it_is_reached` |
| The adapters convert offline (`convert_file` / `convert`); they take no describer | A loader that calls a paid vision model for every picture of every file is a surprise on the invoice. `aconvert(..., describer=...)` is one line for those who want it | - |
| The MCP server returns at most `max_chars` characters per call (100,000 by default), cuts with a note that tells the agent what to do next, and has `document_outline` and `sections` for reading a long document in parts | The agent's context is the scarce resource: a 400-page PDF returned whole fills it and the conversation is over. The converter's own 'stopped' warning is dropped from the answer because the note already says it | `test_mcp_server.py::TestConvertDocument::test_long_document_is_cut_at_max_chars_with_a_note_saying_how_to_read_the_rest`, `test_sections_selects_pages_by_number_or_range`, `TestDocumentOutline` |
| On POSIX the MCP server converts through `IsolatedConverter` (one worker per file, 2 GB, 2 minutes); elsewhere in a thread | The server lives as long as the agent's session, and a document that hangs or balloons must not end it. `IsolatedConverter` is verified on Linux and macOS only (limitations.md) | `TestCommandLine::test_server_speaks_mcp_over_stdio` |
| Without `--root` the MCP server reads any file its user can read; with `--root` (or `OPENDOCKIT_MCP_ROOTS`) only files under those folders, checked on the path after symbolic links are resolved. A root that is not a folder stops the server at start | The server is started by the user for their own agent, like a command-line tool, and has to work with one line of configuration. The restriction is for agents that read untrusted text and could be talked into opening something else; it is checked on the real path because a link inside an allowed folder is the obvious way around it | `TestWhichFilesMayBeRead`, `TestCommandLine::test_root_that_is_not_a_folder_is_an_error_before_the_server_starts` |
| Tool errors are the converter's fixed messages or one of the server's own fixed sentences; nothing of the document or of a parser error is in them | The rule of the whole library (core.md): messages can be shown as they are | `TestConvertDocument::test_malformed_sections_are_refused_with_one_fixed_message`, `test_file_that_cannot_be_converted_reports_the_converter_message` |
| The MCP module is written against MCP SDK 2.x (`MCPServer`) and the extra requires `mcp>=2.0` | 2.0 renamed the server class and changed its module; supporting both would be two code paths for one small file | `TestCommandLine::test_tools_are_described_for_the_agent` |

## Known accepted gaps

- No adapter describes pictures; scanned PDFs come back empty with a warning unless the caller converts with a describer.
- The MCP server speaks stdio only. Remote transports would need authentication and a different answer to "which files".
- On Windows the MCP server has no worker isolation and no time limit of its own.
