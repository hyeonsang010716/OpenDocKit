# Integration decisions (LangChain, LlamaIndex, MCP)

Deliberate decisions of `opendockit.integrations` and `opendockit.mcp_server`. The rule is the same as in [extractors.md](extractors.md): do not revert the decisions in this table. To change one, change its pinning test first and write the reason here.

| Decision | Why | Pinned by |
| --- | --- | --- |
| The adapters live in this package behind extras (`langchain`, `llamaindex`, `mcp`), not in separate distributions. Nothing in `opendockit` imports them. Each adapter module fails on import with the install command when its framework is missing; `mcp_server` imports without the SDK, because its command is installed for everyone, and says the same when it is started | One version, one release and one test run cover the converter and its adapters; a separate package per framework would be three more things to keep in step for about fifty lines each. The price: the adapters are not named the way the frameworks' own catalogues expect (`langchain-…`, `llama-index-readers-…`) | `test_integrations.py`, `test_mcp_server.py` (skipped when the extra is missing) |
| One function (`integrations._documents.pieces`) decides how a result is cut and what its metadata is, for every adapter | An index built with LangChain and one built with LlamaIndex must cite the same page for the same passage | `test_integrations.py::TestLlamaIndexReader::test_load_data_gives_documents_with_the_same_pieces_as_the_loader` |
| `mode="sections"` gives one piece per page, slide or sheet; a document without physical units is one piece in either mode. The adapters do not split by headings or by size | Pages, slides and sheets are facts of the file and the unit people cite. How to chunk prose is the caller's choice, and the frameworks already have Markdown splitters | `TestLangChainLoader::test_sections_mode_gives_a_document_per_sheet_slide_and_page`, `test_document_without_units_is_one_piece_in_either_mode` |
| A piece of a slide or sheet starts with the heading of the full text (`converter.section_heading`); a page carries no `<!-- Page N -->` marker | A sheet read alone without its name, or a slide without its title, has lost the one line that says what the numbers are. A page number is not content: it is `section_index` | same test |
| Metadata values are strings, integers and booleans only: warnings are one string with a line each, and `warnings` / `exceeded` are absent when there is nothing to say | Chroma, Pinecone and others reject lists and nested values in metadata, and the failure appears only when the documents are stored | `TestLangChainLoader::test_metadata_values_are_plain_scalars` |
| A file that cannot be converted raises the converter's `ConversionError`; the loader has no "skip errors" switch. `lazy_load` converts a file only when it is reached | A document missing from an index without a word is the failure nobody notices. The caller who wants to skip can catch the exception around `lazy_load` | `test_file_that_cannot_be_converted_raises_the_conversion_error`, `test_lazy_load_converts_a_file_only_when_it_is_reached` |
| A slide that is only a title is a piece (its heading); a page, sheet or slide with neither text nor title is not. When `sections` finds nothing in the range asked for, the MCP server names the numbers that exist | A deck of divider slides came out empty in `sections` mode. Numbers can have gaps (an empty first sheet), so 'the document has 1 sheet' sent the agent back to sheet 1 | `test_integrations.py::TestLangChainLoader::test_slide_that_is_only_a_title_is_kept`, `test_mcp_server.py::TestConvertDocument::test_note_names_the_numbers_that_exist` |
| A result with no text to hand on gives no document, and one warning with the path and the converter's warnings is logged (`opendockit.integrations`) | An empty Document breaks embedding calls, a Document holding only `<!-- Page 1 -->` markers is noise in the index, and no Document at all is silent: a scanned PDF would vanish from the index without a word. The warnings have no Document to travel on | `TestLangChainLoader::test_file_without_any_text_gives_no_document_and_a_logged_warning` |
| `OpenDocKitReader` reads through the fsspec file system `SimpleDirectoryReader` hands it (`fs=`), and implements `lazy_load_data` | Ignoring `fs` read the local disk for a file that lives in a bucket; the directory reader printed an error and skipped it | `TestLlamaIndexReader::test_file_system_given_by_the_directory_reader_is_used`, `test_lazy_loading_gives_the_same_documents` |
| The adapters convert offline (`convert_file` / `convert`); they take no describer | A loader that calls a paid vision model for every picture of every file is a surprise on the invoice. `aconvert(..., describer=...)` is one line for those who want it | - |
| The MCP server returns at most `max_chars` characters of the document per call (100,000 by default; the note and the warnings come after them), cuts with a note that tells the agent what to do next, and has `document_outline` and `sections` for reading a long document in parts | The agent's context is the scarce resource: a 400-page PDF returned whole fills it and the conversation is over. The converter's own 'stopped' warning is dropped from the answer because the note already says it | `test_mcp_server.py::TestConvertDocument::test_long_document_is_cut_at_max_chars_with_a_note_saying_how_to_read_the_rest`, `test_sections_selects_pages_by_number_or_range`, `TestDocumentOutline` |
| On POSIX the MCP server converts through `IsolatedConverter` (one worker per file, ended after 2 minutes and, on Linux, at 2 GB); elsewhere in a thread | The server lives as long as the agent's session, and a document that hangs or balloons must not end it. `IsolatedConverter` is verified on Linux and macOS only (limitations.md) | `TestWhichFilesMayBeRead::test_conversion_runs_in_a_worker_process`, `TestCommandLine::test_server_speaks_mcp_over_stdio` |
| Without `--root` the MCP server reads any file its user can read; with `--root` (or `OPENDOCKIT_MCP_ROOTS`) only files under those folders, checked on the path after symbolic links are resolved, and by what the folders are (device and inode), not by how their names are spelled. A root that is not a folder, or is empty, stops the server at start | The server is started by the user for their own agent, like a command-line tool, and has to work with one line of configuration. The restriction is for agents that read untrusted text and could be talked into opening something else; it is checked on the real path because a link inside an allowed folder is the obvious way around it. Compared as text, `--root ~/documents` refused files under `~/Documents` on macOS, and a Korean folder name typed composed refused the same name as a directory listing returns it. An empty `--root` (an unset shell variable) used to mean the current folder, and an empty environment variable no restriction | `TestWhichFilesMayBeRead`, `TestCommandLine::test_empty_root_is_an_error`, `TestCommandLine::test_root_that_is_not_a_folder_is_an_error_before_the_server_starts` |
| Tool errors are the converter's fixed messages or one of the server's own fixed sentences; nothing of the document or of a parser error is in them. Text that comes from the document into an answer the server composes (titles and other metadata in the outline, names inside warnings) is put on one line of bounded length. Known accepted gap: an argument of the wrong type (`max_chars: 50.5`) is refused by the SDK's validation, in its words; `sections` is accepted as a number too, the likely slip | The rule of the whole library (core.md): messages can be shown as they are. A title holding line breaks and `Warnings:` added lines to the outline that looked like the server's own | `TestConvertDocument::test_malformed_sections_are_refused_with_one_fixed_message`, `test_file_that_cannot_be_converted_reports_the_converter_message`, `test_sections_may_be_given_as_a_number`, `TestDocumentOutline::test_title_cannot_add_lines_to_the_outline` |
| Both MCP tools carry the read-only hint; a file that cannot be read gives one fixed sentence, not the system's error text. `opendockit-mcp` is installed with the package whether or not the extra is: without the SDK it ends with the install command | Clients decide from the hint whether to ask the user before a call. The command exists in every install because console scripts cannot depend on an extra, and a traceback is not an answer | `TestCommandLine::test_tools_are_described_for_the_agent`, `test_command_without_the_sdk_says_what_to_install`, `TestWhichFilesMayBeRead::test_file_without_read_permission_is_refused_with_a_fixed_message` |
| The MCP module is written against MCP SDK 2.x (`MCPServer`) and the extra requires `mcp>=2.0` | 2.0 renamed the server class and changed its module; supporting both would be two code paths for one small file | `TestCommandLine::test_tools_are_described_for_the_agent` |
| The MCP server announces tools only: the handlers the SDK registers on every server for prompts and resources are removed from its table (a private attribute; when it is not where expected the server works and announces them again) | A client builds the agent's tool list from the announcement. Hermes added `list_resources`, `read_resource`, `list_prompts` and `get_prompt` for this server; they could only return empty lists and cost context in every request. The SDK has no option to leave the handlers out, and writing the server on its low-level class to avoid one private attribute would be much more code to keep | `test_mcp_server.py::TestCommandLine::test_server_announces_tools_and_nothing_it_does_not_have` |
| The Hermes Agent plugin (`hermes-plugin/`) is data only — `plugin.json`, `mcp.json`, one skill — and starts the published console script with `uvx` at one exact release (`opendockit[mcp]==X.Y.Z`) with its dependencies resolved as of one date (`--exclude-newer`); its version is that release's. It passes no `--root` and forwards `OPENDOCKIT_MCP_ROOTS` from the user's environment | The Hermes catalog pins a commit that reviewers read, so the package must not install "whatever is newest" — neither of OpenDocKit nor of its dependencies, whose ranges have no upper bound: a later major release of one of them would break an install nobody changed — and code of ours inside it would be a second copy of the server to keep in step. A root written into the package would be the same folder for every user; an unset forwarded variable is dropped by Hermes, where an empty one would stop the server. The plugin runs nothing when the library is used, so only a test notices when its skill names a tool that no longer exists or the pin moves in one file and not the others | `test_hermes_plugin.py` |

## Known accepted gaps

- No adapter describes pictures; scanned PDFs come back empty with a warning unless the caller converts with a describer.
- The MCP server speaks stdio only. Remote transports would need authentication and a different answer to "which files".
- On Windows the MCP server has no worker isolation and no time limit of its own.
