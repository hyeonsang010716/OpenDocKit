# PDF decisions: borderless table rows and columns

Decisions of the PDF extractor (`src/opendockit/extractors/pdf.py` and the `_pdf_*.py` modules beside it) about row and column judgments of borderless tables: rows with wide cells, overflowed cell lines, an empty top-left cell, and narrow gaps between cells. Split off from [pdf-tables.md](pdf-tables.md)
because of its size limit; the rules are the same: do not revert the decisions in this table. To change one, change the pinning test first and write the reason in the same row.
The conservative criterion (3 or more short pieces × 3 or more rows, [pdf.md](pdf.md)) stays as it is; only the rows that attach to a table found by that criterion are widened.

## PDF borderless table rows and columns

| Decision | Why | Pinned by |
| --- | --- | --- |
| A data row below the header is accepted if it has only one piece wider than the maximum table-cell width and that piece lies within its own header column (after the end of the previous header cell and before the start of the next header cell) (`_wide_cell_in_its_column`). Like a section row, such a row does not count toward the table's minimum row count — the minimum is met, as before, by rows holding only short cells. Exception (round 46): if there is at least one data row with 3 or more cells filled with short cells only, and the table is closed above and below by a single-piece line (title, paragraph) or a distant gap (below, it must be a single-piece line right underneath), a wide-cell row with 3 or more filled cells counts too (in two- or three-row task tables, overflowed rows and long rows were mixed and scattered column-wise). If there are only short rows with fewer than 3 cells, it does not count (letter-spaced item lines of an official letter '가. 일 \| 시 \| …' became a table). Neither do the front part cut off at a row that merges its cells differently (it blocked the path that took that front part first and re-found the whole table with `_split_merged_cells`, breaking a real chronology apart) or a fragment open at the top (the overflowed second line of cell text became the header and the row above was scattered into paragraphs) — `test_pdf_round46.py::TestSmallTableWithAWrappedCellAndAWideCell`. For an overflowed cell line, the threshold for 'how many line heights narrower than the row gap' is 0.5x (`_WRAP_GAP_MIN_RATIO`; the ratio side `_WRAP_GAP_RATIO` 0.6 is unchanged). The line gap of a two-line cell beside a vertically centred cell (`_with_centred_wrapped_cells`) may be up to half a line height + 0.5pt | A Chrome table (4px cell padding) whose '과제명' column, 45% of the page width, wrapped to two lines broke at every wide-cell row and the rows were mixed column-wise (round 35). The overflow line's difference of 6.7pt from the row gap (12.7pt) fell short of 0.6 times the line height (12pt), so it became a separate row, and a centred table has a line gap of exactly half a line height and failed on floating-point error. A body line extending to the next header cell is not accepted | `test_pdf_table_columns.py::TestWideWrappedFirstColumn` |
| A gap of at least 0.4 times the font size (`_NUMBER_GAP_RATIO`) between a number and a number without a space character is also a cell-boundary candidate (`fine_parts`; preceding character a digit, `%` or `)`, following character a digit or sign). Splitting merged pieces of an already found table (`_split_merged_cells`) also uses `fine_parts` (splitting only inside an already found table is unchanged) | The right-aligned amount and the rate of the next column in a Chrome table (cell padding 0.5x) became one cell '1,250 65%', and the gap between a right-aligned numeric cell and a left-aligned '비고' cell (0.75x, no space character) fell short of `_CELL_GAP_RATIO` (0.8x), so '18 2023 신규'·'2024 비고' became one cell (round 35). Digits within one number touch, and there is a space character between words | `test_pdf_table_columns.py::TestWideWrappedFirstColumn`, `TestNarrowColumnGaps::test_right_aligned_numbers_next_to_a_left_aligned_note_column` |
| If the row right above a found table has one piece fewer than the table's first row, all short, starts after the end of the first-column cell, and each piece in turn matches the first row from the second cell on in left edge, right edge or centre, it is a header with an empty top-left cell (`_blank_corner_header`; an empty cell piece is inserted at the front, giving `\| \| 1분기 \|`). Not looked at if accepting rows above (`_table_rows_above`) accepted any row | A quarterly table with an empty first-column header has one header piece fewer than the data rows, so the header fell apart into per-cell paragraphs and the first data row became the header (round 35). A row above that does not fit the columns is left as is | `test_pdf_table_columns.py::TestBorderlessTableWithBlankCorner` |
| If the second row of a borderless table is a line overflowed from the header cells, it is joined to the header cells with a space (`_wrapped_header_line`): in every column where its cell is filled the header cell is filled too; neither row has a numeric value cell (`_FAR_VALUE`) while the data rows below do; and the gap to the header is at most 0.6 times the line height (`_HEADER_WRAP_GAP_RATIO`) and narrower than half the gap to the row below. Known accepted gap: for a two-line header of a table without numeric values the second line stays a row as before | The second line of a two-line header ('판매량 / (대)', '전년 동기 / 대비 증감률') became the first data row '\| \| (대) \| (백만원) \|' and only half of the column names remained (round 36). A row at the same spacing as the data rows is not an overflow line | `test_pdf_table_columns.py::TestBorderlessTwoLineHeader` |
| Between two table-wide horizontal rules (the rule under the header and the bottom border of a three-line table), two or more single-piece lines with the same left edge attached at line spacing (first-cell text) and one value row (continuing at the same height as a first-cell text line, or a values-only row not overlapping the first-cell text horizontally) are grouped into one row (`_with_ruled_wrapped_cells`·`_wrapped_label_row`). Only when the centre of the value row lies within the height of the first-cell text, there is no rule inside the group, and the gaps to the rows before and after the group (inside the rules) are wider than the line gap inside the group. Nothing is grouped outside the rules | In a three-line table with values aligned to the vertical centre or bottom, the leading line of the first cell was set apart above the value row, so the table broke before '판매량' or '\| 값) \| 900 \| 950 \|' became the header, and the remaining rows were scattered cell by cell after the paragraph below the table. With top alignment too, the overflow line of the last row ('원, 부가세 제외)') had no row below and became a paragraph outside the table (round 41). In a table without cell padding the line gap cannot tell whether an overflow line belongs to the row above or below, and grouping outside the rules could attach the paragraph right above the table to a header cell | `test_pdf_ruled_wrapped_cells.py::TestWrappedFirstCellsInAThreeRuleTable` |
| For first-cell text lines of a three-line table, 'attached at line spacing' means at most half a line height + 0.5pt, or the median line gap of paragraphs outside the rules + 1pt (`_paragraph_line_gap`, only single-piece rows whose line gap is at most 2 line heights). If a values-only row sits between the first-cell text lines and its centre is within `_CENTRED_CELL_RATIO` of a line height from the centre of the first-cell text lines (vertical centring), the gaps before and after are not checked, and if lines were collected up to the first line of the next row, only the leading lines whose centre matches are used. If the value is at the same height as a first-cell line (top or bottom alignment), this exception is not used. Known accepted gap: top and bottom alignment in a table with zero vertical cell padding, centring with an odd number of lines of three or more, a table where a cell other than the first overflowed, and a two-column three-line table are not grouped | A three-line table exported by LibreOffice in a Korean font has a line gap of 0.8 times the line height (9.7pt for 12pt characters), so the first-cell lines were not joined and it was read column-wise as '열0, r1c0 … 열1, r1c1 …' (14 of 18 with 3·4 columns, round 42). In a zero-padding table the gap between rows equals the line gap and cannot separate them, and with bottom alignment 'two first-cell lines + the first line of the next row' has the same shape as three lines with the value in the middle, so the first line of the next row was attached to the preceding cell | `test_pdf_ruled_wrapped_cells.py::TestWrappedFirstCellsWithWideLineSpacing` |
| When an already found borderless table is extended upward (`_split_merged_cells`), the original lines of split-off pieces (`_Line.source`) are also added to the already used lines. Splitting merged pieces and the further search (`_splittable`·`_split_line_table_runs`) treat text as letter-spaced, and do not split it, only when two or more single-character Hangul/Hanja pieces follow one another (`_letter_spaced_parts`) | Rows of a table found by splitting at narrow cell gaps were taken again by the table right below, so '기여도 \| 8700 \| 판매량' appeared twice in two tables. '값 단위' of a Chrome three-line table (a 1.3em cell gap merged by pdfminer) was not split because of the single-character piece '값', so the header and first row became paragraphs outside the table and the second row became the header (round 42) | `test_pdf_table_columns.py::TestRowsOfASplitTableAreNotTakenAgain`, `TestOneLetterHeaderCell` |
| The borderless tables of a page are re-searched with their merged pieces split (`_split_merged_cells`) one after another from the top (`_split_runs`): the rows a table took above or below it, and the original lines of its joined cells (`line.joined`), count as used lines for the tables after it. When the rows below a table lead into the first row of another found table — that row has a numeric value cell that is not a year or date (`_YEAR_OR_DATE` — it is not a header of its own such as '구분 \| 2023 \| 2024'), no gap on the way is wider than the median gap between the rows of the two tables + 1pt (with the widest gap, one wide gap inside a table let an equally wide gap between tables through), and no horizontal rule lies in between — the region down to the end of that table, and further down as far as that table would have grown by itself, is searched first and the two become one table only when exactly one table is found that holds every line of both, has at least the columns of each, and has cells on two or more rows in every column holding a split piece; otherwise the table is searched for alone as before | A row merged differently ('광주 \| 5,955 \| 10.8% 감소') between two tables found apart was taken by the table above (downwards) and by the table below (upwards), so it came out in both tables and the one table stayed split in two (audit round). Joining without the header and pitch conditions put a separate product table with its own header ('품목 \| 단가 \| …') under a totals row into the table above, and lost the rows that table grew below itself ('귤') to paragraphs (second review) | `test_pdf_borderless_split_rows.py::TestRowMergedDifferentlyBetweenTwoTables`, `TestSeparateTableBelowARowInNoTable`, `TestNoCellTextInTwoTables` |
| Known accepted gap: a box with only an outer border and horizontal rules and no vertical rules (the '성과측정식' cell of a form) is seen as a one-column box, discarded, and read as body flow — words break at every cell and rows are mixed (the DOCX original is fine). pdfplumber's text-based vertical strategy split cell text in the middle of words and dropped the row above, so it was no better | The column boundaries would have to be estimated separately from character columns for each band between horizontal rules, and the only sample to base this on is a single form (round 42) | — |
| Known accepted gap: when a table with a filled header + borderless data rows (header shading on a borderless Word table) crosses a page, extending the shaded table (`_grown_shaded_table`) accepts only the header and one first unfilled row, so the remaining rows become a paragraph per cell, and cell text that ran over to the top of the next page is read after that page's rows | Accepting several unfilled bands could turn body paragraphs and notes below a filled header into cells (the same boundary as round 40 'a filled header + borderless data are two tables'). All content remains (round 41 review, generator Word→LibreOffice PDF) | — |
| Splitting merged pieces (`_splittable`, an already found table and the row right above it) checks that each piece, not the full line width, is at most the maximum table-cell width (25% of the page width) (the same criterion as `_split_line_table_runs`). The condition that the re-found table be a single table holding every line of the original table is unchanged | When header cells are closer than two character widths and pdfminer merges '1분기 2분기 3분기 4분기' into one line, that line exceeds 25% and could not be split; the header became a paragraph outside the table and the first data row became the header (19 of 42 Chrome borderless and three-line tables, round 43) | `test_pdf_table_columns.py::TestHeaderMergedWiderThanACell` |
| Inside a borderless table, a row in which cell text wraps to two lines and the other cells are aligned to the vertical centre or bottom is accepted as one row (`_table_runs`). Centre alignment is three rows with the remaining cells at a height between the two lines (`_centred_wrapped_row`, the same conditions as `_with_centred_wrapped_cells`); bottom alignment is leading lines set apart above the value row (`_row_with_lead_lines`): the gaps between the lines and to the value row are at most 0.6 times the row gap (before the first data row, the gap to the row above) and narrower by at least 0.5 times the line height, and the line overlaps the same-column cell of the row below horizontally without extending into the column to the right (`_continues_cell` seen in reverse). After a row with a numeric cell, if the value row has no numeric cell it may be a caption above the header of a new table and is not joined. Looked at only after a table has been found (below the header) — so that a caption above a table is not attached to a header cell | With bottom alignment (the default of Excel PDFs) the leading line was set apart, the table split at that row and the first row of the second fragment became the header (if it was the first data row, the header became per-cell paragraphs); a centre-aligned last row was scattered cell by cell with the paragraph below the table wedged in between. In 400 random reportlab tables (bottom alignment by default) the share of rows gathered on one line went from 57% → 65% (269 tables improved, in 4 only the cell positions changed); 0 words lost | `test_pdf_round45.py::TestWrappedRowsOfABorderlessTable` |
| A row in the middle of a borderless table with only one filled cell that is not in the first column (a subtotal amount) is accepted as a table row (`_is_lone_value_row`): it is short and matches the header or the same-column cell of the row above or below in left edge, right edge or centre (the header since round 46: a subtotal in a remarks column empty in every other row found no cell to match and broke the table), its size matches the next row, the gaps above and below are the same row spacing as for a section row (`_at_row_spacing`), and the next row continues the table. After a row with a numeric cell, it is not accepted if the next row has no numeric cell (same as a section row). It does not count toward the minimum row count | Only first-column values were accepted as section rows, so a single value in the second column or later broke the table, the amount fell out as a paragraph and the first data row of the second fragment became the header | `test_pdf_round45.py::TestSubtotalRowInsideABorderlessTable`, `test_pdf_round46.py::TestLoneSubtotalInAnOtherwiseEmptyLastColumn` |
| Below the header of a borderless table, a vertically centred row in which several cells wrap to different numbers of lines (a formula table) is accepted as one row (`_centred_band_row`): in a group of lines whose line gap is at most half a line height or which overlap, there is a stagger with a top-edge difference under 0.75 times the line height; the lines collected per header column (pieces of the same column in the same visual row are joined into one line) continue at line spacing and their centres all match the centre of the group (`_CENTRED_CELL_RATIO`); and there are 3 or more columns with both one-line and multi-line cells. The header and this row alone already make a table. When merged pieces are split and searched again (`_split_merged_cells`), the joined cells are put back as their original lines | Line heights were out of step per cell, so the visual rows were scattered into cell fragments, the table split in two and overflowed pieces ('함량'·'eco-cost') went to other columns. Four formulas in real LibreOffice PDFs (SKIPC·HI MI·0905·EPCM) became one row, and for the compatibilizer the 19%·50% values went to the right rows. Without the one-line-cell condition, an ordinary table whose cells are 4.5pt apart because of fonts was lumped into one row | `test_pdf_round46.py::TestCentredFormulaRowWithCellsWrappedToDifferentHeights`, `test_pdf.py::TestRepeatedMarginsAndBorderlessTables::test_borderless_table_row_is_grouped_when_fonts_put_the_cells_at_different_heights` |
| After two or more data rows of a borderless table have accumulated, the table is cut at a row that has two or more pieces outside the first column, none of which matches in left edge, right edge or centre any same-column cell of the 20 data rows right above (`_OUT_OF_LINE_ROWS`) (`_out_of_line`). The header is excluded from the reference (left-aligned cells under a centred header) | Two borderless tables with different column counts placed a row spacing apart became one table and the cells of the second table went into the wrong columns ('\| 부서 \| 인원 \| \| 비고 \|'). Looking at the whole table is quadratic time for long tables | `test_pdf_round45.py::TestBorderlessTablesWithDifferentColumnsNextToEachOther` |
| An overflow line below the last row of a borderless table is joined to the cell if it is inside the same filled rectangle as that row (`_Page.bands`, `_shade_bands`) (`_in_the_band_of`: covering the top of the row, the bottom of the lines, and the horizontal range). A table without fill stays as before, with the line below the table (accepted gap, pdf.md) | The last row's '운영' in a striped table with whole rows filled (a fill without cell boundaries, so it is read as a borderless table, not a shaded table) became a paragraph below the table even though it was inside the filled band | `test_pdf_round45.py::TestWrappedLastRowOfAStripedTable` |
| Known accepted gap: in a borderless table, (1) a row in which a single first-cell text piece exceeds the maximum table-cell width (a cell 40% of the page width merged with another cell), (2) a row in which several columns overflowed at once ('체험장으 / 로.') and rows with many empty cells in a sparse 3-column table, and (3) a row whose cell baselines are off by more than `_TABLE_ROW_TOLERANCE` (2.5pt) because of a fallback font, break the table or scatter the cells into line-by-line paragraphs. The content remains | The only basis for deciding whether an overflow line attaches to the row above or below, or whether staggered baselines are the same row, is the line gap, which could pull body paragraphs into the table. Only 35% of top-aligned and 11% of centre-aligned LibreOffice borderless tables were intact (round 43 review) | — |
| The repeated-line rule protects the original lines of a table cell joined from several lines (`line.joined`) as well as the cell | The first line of a wrapped cell in the top row of a table repeated on 3 pages was deleted, and the header and first row fell out of the table | `test_audit_pdf_tail.py::TestJoinedCellLinesAtThePageTop` |
| The per-column table search on a two-column page counts the original lines of joined cells as table lines (`_column_table_runs`). Known accepted gap: `line.source` there is still not counted (not reproduced); `joined` is counted in `taken` of `_aligned_table_runs` (see `_split_runs`) | The lines of a centred row with cells of several lines became a second table and came out twice | `test_audit_pdf_tail.py::TestJoinedCellLinesOnATwoColumnPage` |
