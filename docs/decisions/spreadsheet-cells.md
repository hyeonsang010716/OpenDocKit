# Spreadsheet cell decisions

Decisions of the Excel extractor (`spreadsheet.py`) about interpreting cell values, pictures in cells, form controls, default-password XLS, cell comments, the cell of a floating picture and time formats. Split off from [spreadsheet.md](spreadsheet.md);
the rule is the same: do not revert the decisions in this table. To change one, change its pinning test first and write the reason in the same row.
The pinning tests are all in `test_spreadsheet_cell_values_and_controls.py` (a file name is given only for other files).

## Cell values

| Decision | Why | Pinned by |
| --- | --- | --- |
| Only while this module is reading an XLSX (context variable `_READING`) is the cell parsing of openpyxl's sheet parser (`WorkSheetParser.parse_cell`) wrapped (`_tolerant_parse_cell`, a deliberate replacement in a private class — the same approach as the `from_excel` replacement). A cell that cannot be parsed keeps the text written in the file (`1,5`, `abc`, `NaN` in a numeric cell; a non-ISO date `2024.01.05`), booleans `true`/`false` become TRUE/FALSE, and a shared-string index with no string to point to is left blank, with a count warning. An out-of-range, empty or non-numeric cell style index (`s="57"`, `s=""`) is the default style (no warning; the number of cell styles is learned by wrapping `apply_stylesheet`). Row and column settings (`<col>`, `<row ht>`) are not used in conversion and are not parsed while reading. Full load and streaming both pass through the same function | A single cell rejected the whole document as 'corrupted' (shared-string and style indexes raised an uncaught IndexError: 'could not be parsed'). Excel and LibreOffice open it. Fixing a copy and re-reading cannot be used because streaming fails in the middle of reading rows. The cost of the wrapper is within measurement error at 60,000 rows × 10 columns | `TestOneMalformedCellValue`, `test_core_spreadsheet.py::TestMalformedViewAndPrintSettings::test_empty_cell_style_inside_the_cells_reads_as_the_default_style` |
| Only while reading (`_READING`), openpyxl's shared-string table reading (`read_string_table`, `read_rich_text`) is replaced too (`_tolerant_string_table`): a string whose character-format or phonetic attributes are out of spec (`color rgb="#FF0000"`, `sz val="10,5"`, `u val="bogus"`, `rPh sb="abc"`) has the formatting discarded and only the text read (`_plain_string`, the same text as `Text.content`). The same defect in an inline string (`t="inlineStr"`) is handled by `_raw_cell` with the text of `<is>`. The text is intact, so there is no warning. Known accepted gap: the superscript/subscript marks of that string are lost as well | A single formatting attribute of a single string rejected the whole shared-string table, i.e. the whole document, as 'corrupted' (LibreOffice opens it). An inline string became blank with the wrong warning that 'the text written in the file was carried over as is' | `test_spreadsheet_damaged_parts.py::TestMalformedTextRunProperties` |
| An ISO date and time joined by a space in a `t="d"` cell (`2024-01-05 13:00:00`) is re-read with `T` so the time is kept (`_tolerant_parse_cell`). When the time is 0 it is still the date only (`_format_value`) | openpyxl's ISO regular expression matched only the date part and 13:00 disappeared without a warning (a value joined with `T` already showed the time) | `TestIsoDateCellsWithoutAFormat` |
| For an Excel 365 'Place in Cell' picture cell (`t="e" vm="N"` + `#VALUE!`) the picture is found through value metadata (metadata.xml) → rich values (rdrichvalue, rdrichvaluestructure) → the richValueRel relationship and put **in that cell** as a placeholder (`Extraction.add_image`; the alt text is the structure's `Text` key). Data-type cells (stocks, geography etc.) give the `_DisplayString` text. A vm error cell that cannot be resolved is blank + a count warning. Pictures are registered when the row is read (`_cell_text` → `_CellReading.picture_text`; cells after stopping at the limit are not registered). Blank with `extract_images=False`. Known accepted gap: web pictures (_webimage) and other structures are blank + a warning | Picture cells were read as `#VALUE!` errors and a product photo table became a table of errors. Gathering the pictures after the table loses which row a photo belongs to | `TestPicturesAndDataTypesPlacedInCells` |

## Drawing objects

| Decision | Why | Pinned by |
| --- | --- | --- |
| Form-control check boxes and option buttons become `☒ label`/`☐ label` (the same characters as DOCX form fields, HWPX and HTML), after the table, in positional order with the other drawing objects. XLSX reads the sheet's VML drawing (legacyDrawing; `x:ClientData ObjectType="Checkbox"`/`"Radio"`, state `x:Checked`=1, position `x:Anchor`) with a parser that skips broken tags, and it is also ☒ when the control properties (`checked="Checked"` in ctrlProps, linked to the VML shape through the sheet's `<control shapeId>`) say selected (`_form_controls`). XLS puts ☒ in front of the following TXO label when the first 2 bytes of FtCblsData (0x12, else 0x0A) of the OBJ record (types 0x0B, 0x0C) are 1 (`_xls_choice_mark`). Cell comments (Note), buttons and list boxes are not read. Known accepted gap: the 'mixed' (2) state is ☐ | XLSX lost even the label and XLS the selected state, so nobody could tell which of '동의함' (I agree) and '동의하지 않음' (I do not agree) was chosen on a consent form | `TestFormControlCheckBoxes` |
| VML is read as a bonus: the inside of a label text box (`v:textbox`) is an HTML fragment, so the tags are stripped and HTML named character references (`&nbsp;`) are turned into numeric references before reading (`_plain_text_boxes`; when the closing text-box tag is missing, what follows stays as is), and unclosed void HTML tags outside text boxes (`<br>`, `<hr>`, `<img>`, `<wbr>`) are closed before reading (`_VML_VOID_TAG` — `<` is not allowed in the attribute position, so it is linear). Unreadable VML (an empty part, junk bytes) only skips the check boxes (`_vml_root`, no warning). A multi-line label joins its lines directly, the same as with a closed `<br/>` | The parser that skips broken tags pushed elements down at every unpaired `</font>`, so `x:ClientData` ended up inside `v:textbox`, and the selected '☒ 동의<br>함' dropped out without a warning leaving only '☐ 동의하지 않음' (the meaning was reversed). One empty VML made the whole document 'could not be parsed' (it opened before check boxes were read). (Later) `<br></br>` and an unclosed `<p>` pushed the shapes again and check boxes were lost, and 60,000 `<br` without `>` (6 KB XLSX) took 78 s | `test_spreadsheet_damaged_parts.py::TestDamagedFormControlDrawing` (`test_html_shaped_label_keeps_both_check_boxes`, `test_many_unfinished_tags_take_linear_time`) |
| CONTINUE fragments after an XLS drawing record are appended in place to a `bytearray` (`_scan_xls_drawings`) | Creating new bytes every time was quadratic in time and memory (16 MB chain 2.2 s, 1.1 GB; 48 MB 11 s, 3.3 GB → 0.03 s, 280 MB) | `test_spreadsheet_damaged_parts.py::TestLongDrawingContinuation` |
| SmartArt in a sheet's drawing part (`dgm:relIds` of a graphicFrame; the data model is the `r:dm` relationship) becomes, at its position, the same `_shared.render_smartart` nested list as in PPTX/DOCX (`_drawing_items` → `_chart_text`). The cache of drawn shapes (diagrams/drawing*.xml) is not read (the same text would come out twice) | Organization charts and process diagrams were dropped whole | `TestSmartArtOnASheet` |

## XLS encryption

| Decision | Why | Pinned by |
| --- | --- | --- |
| When the FILEPASS right after the workbook BOF is RC4 (MD5 of standard 1.1; SHA-1 with 40/128 bits of CryptoAPI 2–4.2) and the verifier matches the default password `VelvetSweatshop`, the stream is decrypted (a new key per 1,024-byte block; plaintext records and the first 4 bytes of BOUNDSHEET excluded) and handed to xlrd and the picture and formula checks. FILEPASS is replaced by a record type xlrd does not know (0x0FFF) so that lengths and sheet positions are kept (`_without_default_password`). Other passwords and XOR obfuscation remain a 'password-protected document'. No dependency (msoffcrypto-tool) is added; RC4 and the key derivation are implemented directly (about 0.1 s/MB, only for default-password files) | Excel also encrypts with the default password files that do not ask the person opening them for a password (workbook protection etc.). Excel and LibreOffice open them straight away, yet they were rejected. Known accepted gap: files with XOR obfuscation (Excel 95 style) are rejected | `TestXlsEncryptedWithTheDefaultPassword` |
| Cases rejected because of one row or style value rather than one cell are read too: a row number that is not an integer (`<row r="abc">`, `r="1.5"`) is a row without a number (following the previous row) (`_tolerant_parse_row`; cells are placed by their own address so nothing is lost; no warning), a fillId/xfId over 2³¹ (OverflowError) goes to the style retry that keeps only the display formats (`_repaired_copies`), and a number that becomes infinite (`1E+400`, `-1E+400`) is a cell that does not fit its type (original text + a warning) | A single value made the whole document 'corrupted'; `+1E+400` became `inf` without a warning, and `-1E+400` in a date/time format was rejected with OverflowError | `test_spreadsheet_cell_values_and_controls.py::TestOneMalformedCellValue` (`test_row_number_that_is_not_a_whole_number_is_ignored`, `test_style_number_too_large_for_an_integer_reads_with_the_number_formats`, `test_number_too_large_for_a_float_is_kept_as_its_text`) |

## Cell comments, the cell of a floating picture, time formats

The pinning tests are in `test_spreadsheet_notes_pictures_and_times.py`.

| Decision | Why | Pinned by |
| --- | --- | --- |
| Cell comments go at the end of the sheet (after pictures and text boxes) in cell order as `> Comment(author, cell E5, on "row text: cell text"): text` (`_shared.comment_line(cell=)`). The row text is the first text cell of that row that is not the commented cell (number-shaped ones excluded); when the commented cell is the first text cell of the row, the cell text only. XLSX reads directly from the comments part in the ZIP for both full load and streaming (`_xlsx_comments`); Excel 365 threaded comments are read from threadedComments + the workbook's persons, replies included (`> Reply(author): …`), and the old-format copy in the same cell (author `tc={id}`) is left out. A leading `author:` in the comment text is removed. XLS uses xlrd's NOTE (`cell_note_map`). They count towards the character limit. There is no option to turn them off (same as DOCX). A sheet that is over the limit does not have its comments read. Known accepted gap: formatting and pictures inside comments are discarded | Comments (review remarks) dropped out without a warning (same direction as DOCX/PPTX/HWPX comments). The table has no row and column numbers, so the cell address alone does not tell which value is meant. The old copy is the notice '[Threaded comment] Your version of Excel…'. Confirmed with XLSX and XLS re-saved by LibreOffice | `TestXlsxCellComments`, `TestXlsCellComments` |
| When two or more pictures float on an XLSX sheet, the cell the picture is placed on and the text of that row are put in front of the picture, `(cell C2: 제품A)` (`_SheetRows.place`). Not added for a single picture (logo, stamp) or for the same picture file placed as many times as the repeated-picture threshold (`repeated_image_threshold`) (an icon on every row — erased as a repeated picture). Nor for a picture not tied to a cell (absoluteAnchor). Known accepted gap: the cell note in front of a picture erased as small or decorative stays; XLS pictures get no note because their position is not read | A sheet with a product photo on every row (400 rows) ended in nothing but 400 `[Image]` after the table, so even with descriptions nobody could tell which product a photo showed. The decision to put pictures after the table stands. The number of placements per picture file is counted in one pass (recounting per picture took 40 s for 200,000 anchors) | `TestFloatingPictureCells` |
| A time format with hours (h) is written as the format says (`_clock_text`): `h`/`hh` digits, 12-hour clock for `AM/PM`/`A/P` (오전/오후 for the Korean locale `[$-412]`, `[$-ko…]`), quoted/backslash literals (`h"시" mm"분"` → `14시 30분`), truncation below the smallest unit shown. A format that shows date and time together is `YYYY-MM-DD HH:MM` (seconds only when the format shows them; 24-hour clock). `mm:ss` without hours is `00:01:44` (deliberate — `01:44` reads as 1 hour 44 minutes). Elapsed time follows the format only when the format has quoted literals (`[h]"시간" mm"분"` → `36시간 00분`), otherwise `26:00` as before | `h:mm`, `h:mm AM/PM` and `h"시" mm"분"` cells went out as the 24-hour `18:03:40` with seconds attached, and a format with unit literals as `36:00`. The date shape stays `YYYY-MM-DD` (`_date_text`; year and month literals are not imitated) | `TestTimeFormats`, `test_spreadsheet.py::TestTimeDisplay`, `TestDateTimeAtMidnight` |
| The `… is out of range` that openpyxl's style list (`CellStyleList.__getitem__`) prints to standard output for an out-of-range index is removed by replacing that method in the module with the same behaviour without the output (the IndexError stays — it leads to the re-read). `contextlib.redirect_stdout` is not used | The server's standard output was cluttered. `redirect_stdout` is process-wide and hides the output of concurrent conversions and of the caller as well | `test_spreadsheet_damaged_parts.py::TestNamedStyleOutOfRange::test_out_of_range_style_number_prints_nothing` |
| Excel 2003 XML: the named time formats (Long, Medium, Short Time) are times, and General Date is a date format (date only at midnight — same as Excel; singled out through `_XML_GENERAL_DATE`, which carries a marker bracket section). Scientific gives the raw value (exponent formats are not imitated), Euro Currency is `€#,##0.00`, and Yes/No, True/False, On/Off give Yes/TRUE/On for non-zero. An English name not in the table (made only of words, spaces and `/` and containing a character outside the date-code letters) is the General format. A numeric cell (`ss:Type="Number"`) with a date/time format (openpyxl `is_date_format`) is taken for a serial number and becomes a date, time or elapsed time (below 1 a time). Known accepted gap: the 1904 date system (`x:Date1904`) is not looked at | A time cell went out as `2024-03-05` and a numeric cell with a date format as `45356`. Names missing from the table were caught by `is_date_format` (the s, y, d in the name), so 0.000123 became `00:00:11`, 1234.5 became `1903-05-18` and the 1 of Yes/No became `1900-01-01` | `test_spreadsheet.py::TestXmlSpreadsheetDatesAndTimes`, `TestXmlSpreadsheetNamedFormats`, `TestDateTimeAtMidnight::test_xml_general_date_at_midnight_shows_only_the_date` |

## Parts the converter reads itself, LibreOffice XLS chart sheets

The pinning tests are in `test_office_round43.py`.

| Decision | Why | Pinned by |
| --- | --- | --- |
| Sheet parts the converter does not read: while this module is reading, openpyxl's sheet parser reads only cells (`row`) and merges (`mergeCells`) (`_parse_cells_and_merges`; the remaining tags are `_SHEET_PARTS_LEFT_UNREAD` — table-definition list, hyperlinks, data validation, conditional formatting, auto filter, sheetPr (tab colour), page breaks, protection, views, print, extensions), and comments, drawings and pivot tables are taken out of the sheet relationships (`_dependents_left_to_openpyxl`, `_RELATIONS_LEFT_UNREAD`). Called from outside, it behaves as originally. Charts, pictures and comments are read directly from the ZIP by `_drawing_blocks` and `_xlsx_comments`. Hyperlink addresses are not converted. Pictures and charts whose target part is missing, and those of a drawing whose relationship part (`drawing*.xml.rels`) is broken, are left out with a warning that items without relationship information were left out; a broken comments part drops only those comments, with a warning naming the sheet | openpyxl's parsing of things the result does not use rejected the whole workbook as 'corrupted' for a single chart `legendPos val="right"`, picture `prst="odd"`, comment `authorId="x"`, broken comments XML, `dataValidation type="foo"`, `tabColor rgb="red"`, `hyperlink ref=""`, table `totalsRowCount="x"` or missing pivot `cacheId` (round 43 only blocked the parsing of drawings and comments. Streaming was rejected on sheet settings too). A broken comments part was dropped without a warning | `TestPartsTheConverterReadsItself`, `test_office_round44.py`, `test_spreadsheet.py::TestMissingPartRelationships`, `test_spreadsheet_damaged_parts.py::TestDamagedDrawingRelationships` |
| XLSX document properties and chart sheets: while this module is reading, openpyxl does not read custom properties (docProps/custom.xml) (`read_custom`), and when the document properties (core.xml) cannot be read only the title (dc:title) is looked up directly (`_properties_or_title`; no title when the XML is broken). A chart sheet is kept in the sheet list by name only (`_chartsheet_without_parts` — the chart comes from `_drawing_blocks`). No warning. Called from outside, it behaves as originally | Only the title is used in the result, yet a creation date written as a date only, which is valid W3CDTF (`2024-01-05`), a `0000-00-00` print date, `abc` in `vt:i4` or one broken XML rejected the whole workbook (DOCX/PPTX with the same core.xml are read). A chart sheet without a relationships file (made by openpyxl without a chart) was rejected with AttributeError | `test_office_round45.py::TestDocumentPropertiesTheConverterDoesNotNeed`, `TestChartSheetWithoutRelationships` |
| When an ordinary XLS sheet without cells holds a sheet chart (BOF type 0x20 inside the sheet substream), it warns with the same wording as for a chart sheet (type 2) (`_xls_sheets_holding_charts`). An XLS chart on a sheet with cells is dropped without a warning as before (Known accepted gap — XLS charts are not carried over) | LibreOffice saves a chart sheet as an ordinary sheet + a sheet chart, so that sheet disappeared without a warning | `TestXlsChartSheetSavedAsAWorksheet` |
